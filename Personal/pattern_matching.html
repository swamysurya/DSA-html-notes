1. The Exact String Pattern Matching Problem

Formal definition, sliding window paradigm, why Naive backtracks, and the revolutionary KMP LPS observation

String Algorithms • Unit 8

💡 Teacher's Desk Memo:

"Whenever you press Ctrl + F in a browser, search a DNA nucleotide sequence in bioinformatics, or grep a keyword in a 10 GB log file, pattern matching algorithms run behind the scenes. The Naive method slides the pattern one step at a time and forgets everything it learned whenever a mismatch occurs. The Knuth-Morris-Pratt (KMP) algorithm recognizes that the pattern itself holds clues about where to resume matching, so the text pointer never moves backwards!"

Formal Problem Statement

Given two character arrays (strings):

  • Text string T[0 .. n-1] of length n.
  • Pattern string P[0 .. m-1] of length m, where typically m ≤ n.

Objective:

Find all starting indices (shifts) s where 0 ≤ s ≤ n - m such that the substring in T starting at s matches P character-by-character:

T[s + j] == P[j]   ∀ j ∈ {0, 1, ..., m - 1}

Core Foundations for KMP: Prefixes, Suffixes & The LPS Array

What is a Proper Prefix & Suffix?

Consider string "ABCAB":

  • Prefixes: ε, "A", "AB", "ABC", "ABCA", "ABCAB"
  • Proper Prefixes: All prefixes excluding the whole string: "A", "AB", "ABC", "ABCA"
  • Proper Suffixes: All suffixes excluding the whole string: "B", "AB", "CAB", "BCAB"
Notice that "AB" is both a proper prefix and a proper suffix! Its length is 2.

The LPS Table (π table)

lps[i] stores the length of the Longest Proper Prefix of P[0..i] that is also a Suffix of P[0..i].

Why does this avoid backtracking?

If a mismatch happens after matching j characters, we already know the first lps[j-1] characters of the pattern match the end of what we just matched in the text! We slide the pattern directly to j = lps[j-1]!

LPS Array Walkthrough for Pattern: "ABABCABAB"

Index i 0 1 2 3 4 5 6 7 8
Char P[i] A B A B C A B A B
LPS Value 0 0 1 2 0 1 2 3 4

Explanation: At index 8, the substring is "ABABCABAB". The longest proper prefix that is also a suffix is "ABAB" (length = 4). Hence, lps[8] = 4.

At a Glance: Naive vs KMP

Feature 1. Naive (Brute Force) 2. Knuth-Morris-Pratt (KMP)
Preprocessing Phase None ($O(1)$) $O(m)$ to construct LPS array
Text Pointer Behavior Backtracks to s + 1 on mismatch Never backtracks! Strictly monotone non-decreasing
Worst-Case Time $O((n - m + 1) \cdot m) \approx O(n \cdot m)$ $O(n + m)$ strictly linear!
Auxiliary Space $O(1)$ $O(m)$ for LPS table
Best Practical Fit Short text, natural language with low character repetitions Bioinformatics (DNA/RNA sequences), streaming text, repetitive strings

🐢 Part A: Naive Pattern Matching Sequential Trace

Slides shift by shift ($s = 0, 1, 2, \dots$), checks characters from left to right, and resets on failure.

Action 1: Shift s = 0 (Align at T[0])

Mismatch at j = 4

Compare P[0..3] with T[0..3]: "ABAB" matches! Next, compare T[4] = 'D' with P[4] = 'C'. Mismatch!

Naive Wasteful Consequence: We matched "ABAB", but the algorithm completely forgets this! It increments shift to s = 1 and starts matching from scratch.

Action 2: Shift s = 1 (Align at T[1])

Mismatch at j = 0

Compare T[1] = 'B' with P[0] = 'A'. Immediate mismatch!

Action 3: Shift s = 2 (Align at T[2])

Mismatch at j = 2

Compare T[2..3] with P[0..1]: "AB" matches. Then T[4] = 'D' vs P[2] = 'A' mismatches! Notice character 'D' at T[4] was examined three separate times!

Action 4: Shifts s = 3 .. 9, then Shift s = 10

Pattern Found at Index 10!

Shifts s = 3, 4, 5, 6, 7, 8, 9 all fail after 1 to 4 comparisons. Finally, at shift s = 10, all m = 9 characters match identically!

Total Comparisons Done by Naive Algorithm:

Across all shifts, Naive performed 27 character comparisons to locate the single match at index 10.

⚡ Part B: Knuth-Morris-Pratt (KMP) Sequential Trace

Phase 1 computes the LPS table in $O(m)$ time. Phase 2 searches the text in $O(n)$ time with zero backtracks in text pointer i.

Phase 1: Construction of the LPS Table for "ABABCABAB"

We use two pointers: len (length of previous longest prefix suffix, starts at 0) and i (current pattern index, starts at 1).

Step i P[i] len P[len] Comparison & Rule lps[i] Assigned
Base 0 A - - Always 0 for first char 0
1 1 B 0 A 'B' ≠ 'A', len == 0 → lps[1]=0, i++ 0
2 2 A 0 A 'A' == 'A' → len++, lps[2]=len, i++ 1
3 3 B 1 B 'B' == 'B' → len++, lps[3]=len, i++ 2
4 4 C 2 A 'C' ≠ 'A' → len=lps[len-1]=lps[1]=0. Then 'C' ≠ P[0] → lps[4]=0 0
5 5 A 0 A 'A' == 'A' → len++, lps[5]=1, i++ 1
6 6 B 1 B 'B' == 'B' → len++, lps[6]=2, i++ 2
7 7 A 2 A 'A' == 'A' → len++, lps[7]=3, i++ 3
8 8 B 3 B 'B' == 'B' → len++, lps[8]=4, i++ 4

Phase 2: Text Search Execution ($i$ never goes backward)

KMP Event 1: Matching at Start → Mismatch at T[4] ('D') vs P[4] ('C')

j = lps[4 - 1] = lps[3] = 2

We matched "ABAB" ($j = 4$). Then $T[4] = \text{'D'}$ mismatches $P[4] = \text{'C'}$.
Instead of setting $i = 1$, KMP knows the suffix "AB" matches the prefix "AB"! We set j = lps[3] = 2, keeping i = 4!

KMP Event 2: Immediate Fallback to j = 0, then i++ past 'D'

i advances to 5

At $j = 2$, $P[2] = \text{'A'}$ still does not match $T[4] = \text{'D'}$. KMP sets $j = lps[1] = 0$. Since $j = 0$ and still no match, $i$ increments to 5! The character 'D' is bypassed forever.

KMP Event 3: Full Alignment & Match Detected at Index 10!

j == m (9 matches) → Output index (19 - 9 = 10)

From $i = 10$ to $i = 18$, all 9 characters match with $j = 0$ to $8$ consecutively! When $j = 9 = m$, we record match at index i - j = 19 - 9 = 10. KMP then resets $j = lps[8] = 4$ to search for overlapping occurrences.

Total Comparisons Done by KMP Algorithm:

KMP solved the exact same problem with only 21 character comparisons (and strictly 0 backward movements of pointer i). On large or repetitive texts, this difference becomes astronomical!

#include <iostream>
#include <string>
#include <vector>

// Function: naivePatternSearch
// Returns: A vector of all starting indices in 'text' where 'pattern' occurs
std::vector<int> naivePatternSearch(const std::string& text, const std::string& pattern) {
    int n = text.length();
    int m = pattern.length();
    std::vector<int> matchIndices;

    // Loop through all valid shift positions s from 0 up to n - m
    for (int s = 0; s <= n - m; ++s) {
        int j = 0;

        // Check if all m characters match starting at text[s + j]
        while (j < m && text[s + j] == pattern[j]) {
            j++;
        }

        // If the pattern pointer completed its sweep (j == m), a match is found!
        if (j == m) {
            matchIndices.push_back(s);
        }
    }

    return matchIndices;
}

int main() {
    std::string text = "ABABDABACDABABCABAB";
    std::string pattern = "ABABCABAB";

    std::vector<int> results = naivePatternSearch(text, pattern);

    std::cout << "--- Naive Pattern Search ---\n";
    std::cout << "Found at index: ";
    for (int idx : results) {
        std::cout << idx << " ";
    }
    std::cout << "\n";

    return 0;
}

#include <iostream>
#include <string>
#include <vector>

// Step 1: Preprocess pattern to compute the LPS array
// Time Complexity: O(m) | Space: O(m)
std::vector<int> computeLPSArray(const std::string& pattern) {
    int m = pattern.length();
    std::vector<int> lps(m, 0);

    int len = 0; // Length of previous longest prefix suffix
    int i = 1;   // Pointer starts at second character

    // Loop calculates lps[i] for i = 1 to m - 1
    while (i < m) {
        if (pattern[i] == pattern[len]) {
            len++;
            lps[i] = len;
            i++;
        } else {
            // Mismatch: len != 0, fall back to previous longest prefix length
            if (len != 0) {
                len = lps[len - 1]; // Crucial: do not increment i here
            } else {
                // len is 0, no prefix suffix found
                lps[i] = 0;
                i++;
            }
        }
    }
    return lps;
}

// Step 2: KMP Search function
// Time Complexity: O(n) | Space: O(m)
std::vector<int> KMPSearch(const std::string& text, const std::string& pattern) {
    int n = text.length();
    int m = pattern.length();
    std::vector<int> matchIndices;

    if (m == 0 || n < m) return matchIndices;

    // Precompute the LPS array
    std::vector<int> lps = computeLPSArray(pattern);

    int i = 0; // Pointer for text (NEVER decreases!)
    int j = 0; // Pointer for pattern

    while (i < n) {
        if (text[i] == pattern[j]) {
            i++;
            j++;
        }

        // Entire pattern matched!
        if (j == m) {
            matchIndices.push_back(i - j); // Match starts at (i - j)
            j = lps[j - 1];                // Reset j for overlapping matches
        } 
        // Mismatch after j matches
        else if (i < n && text[i] != pattern[j]) {
            if (j != 0) {
                j = lps[j - 1]; // Smart shift using LPS table!
            } else {
                i++;            // Advance text pointer
            }
        }
    }

    return matchIndices;
}

int main() {
    std::string text = "ABABDABACDABABCABAB";
    std::string pattern = "ABABCABAB";

    std::vector<int> matches = KMPSearch(text, pattern);

    std::cout << "--- KMP Pattern Search ---\n";
    std::cout << "Pattern found at index: ";
    for (int idx : matches) {
        std::cout << idx << " ";
    }
    std::cout << "\n";

    return 0;
}

Rigorous Complexity Comparison & Worst-Case Proofs

🐢 Naive Algorithm Complexity

  • Best Case: O(n). Occurs when mismatch happens on the very first character (P[0]) for every shift. Outer loop runs $(n - m + 1)$ times with 1 comparison each.
  • Worst Case: O((n - m + 1) × m) ≈ O(n × m).
    Degenerate Input Example:
    Text: "AAAAAAAAAAAA" (n = 12)
    Pattern: "AAAAB" (m = 5)
    Every shift matches 4 'A's before failing on 'B', repeating $(12 - 5 + 1) \times 5 = 40$ operations!
  • Space Complexity: O(1) auxiliary memory (only integer pointers s and j).

⚡ KMP Algorithm Complexity

  • LPS Preprocessing Time: O(m). Although the inner condition len = lps[len-1] can execute repeatedly, amortized analysis proves the value of len increases at most $m$ times, so it can decrease at most $m$ times.
  • Matching Search Time: O(n). In the search loop, i strictly increases up to $n$. Pointer j only falls back via LPS at most as many times as it was incremented.
  • Total Time Complexity: O(n + m) across ALL cases (Best, Average, and Worst)!
  • Space Complexity: O(m) auxiliary memory for the lps table.
Algorithm Best Case Time Average Case Time Worst Case Time Auxiliary Space
Naive Search O(n) O(n) (natural text) O(n × m) O(1)
Knuth-Morris-Pratt (KMP) O(n) O(n + m) O(n + m) O(m)
