🎒 0/1 Knapsack Problem Dynamic Programming

Problem Statement

Formal Formulation, 0/1 Constraints & Two Illustrative Examples

Tab 1 • Problem Statement

📌 1. Problem Statement

We are given a carrier bag (knapsack) of maximum weight capacity M (or W) and a set of n discrete, indivisible objects.

  • Each object i (where 1 ≤ i ≤ n) has an associated positive profit pi (or value vi).
  • Each object i has an associated positive weight wi.
  • The knapsack can withstand a maximum total weight of M.
  • 0/1 Constraint: Objects are solid and indivisible (e.g., electronic appliances). Fractions cannot be taken. For each object i, we define a binary decision variable xi:
    xi = 1 (Item i is included) xi = 0 (Item i is excluded)

Formal Mathematical Formulation:

Objective Function

🎯 Maximize Total Profit:   Z = ∑ (pi · xi)   [for i = 1 to n]

Capacity Constraint

⚖️ Subject to:   ∑ (wi · xi) ≤ M   [for i = 1 to n]

Binary Decision Constraint

🔒 xi ∈ {0, 1}   for each i ∈ {1, 2, ..., n}

📊 2. Two Examples (in Table Format)

Example 1 (Knapsack Capacity M = 8, n = 4)

Object 1 2 3 4
Profits (p) 1 2 5 6
Weights (w) 2 3 4 5

💡 Output Explanation:

I choose Object 2 and Object 4 because they give the maximum profit:

  • Total Profit: 2 + 6 = 8
  • Total Weight: 3 + 5 = 8 (fits within capacity M = 8)
  • Selected: Object 2 and Object 4 give max profit.

Example 2 (Knapsack Capacity M = 5, n = 3)

Object 1 2 3

I choose Object 1 and Object 3 because they give the maximum profit:

  • Total Profit: 10 + 50 = 60
  • Total Weight: 1 + 4 = 5 (fits within capacity M = 5)
  • Selected: Object 1 and Object 3 give max profit.

🎯 DP Decision Rule & Cell Meaning: Comparing Two Options Pick Max Profit
💡 What does any cell V[i, w] actually mean in simple terms?

"If my bag capacity was only w kg, and I could only choose from the first i items, what is the maximum profit I could achieve?"

For example, what does V[3, 5] mean?
It means: Considering only the first 3 items (Obj 1, 2, 3), what is the maximum profit we can pack into a 5 kg bag?

Option 1: Don't Take Item i

Skip item i. Keep best profit from previous i−1 items with the same capacity w:

V[i − 1, w]

For V[3, 5]: V[2, 5] = 3

Option 2: Take Item i

Put item i in bag (+Pi profit). Fill remaining w − wi space with previous items:

V[i − 1, w − wi] + Pi

For V[3, 5]: V[2, 5 − 4] + 5 = 0 + 5 = 5

V[i, w] = max( V[i − 1, w],   V[i − 1, w − wi] + Pi ) For V[3, 5]: max(3, 5) = 5  (Option 2 gives higher profit!)

📝 2. Step-by-Step Row-by-Row Filling Explanation

Step 0: Base Conditions (Row 0 & Column 0)

Row 0 (i = 0): When we consider 0 objects, no matter what capacity w is available, the profit is always 0: V[0, w] = 0 for all w ∈ {0, 1, ..., 8}.

Column 0 (w = 0): When the knapsack capacity is 0 kg, it cannot hold any object, so profit is 0: V[i, 0] = 0 for all i ∈ {0, 1, 2, 3, 4}.

Step 1: Filling Row i = 1 (Object 1: w₁ = 2, p₁ = 1)

w₁ = 2, p₁ = 1
  • For w = 1: Since w₁ = 2 > 1, Object 1 is too heavy to fit into 1 kg capacity. Copy from above: V[1, 1] = V[0, 1] = 0.
  • For w = 2: Object 1 fits exactly (w₁ = 2 ≤ 2)!
    V[1, 2] = max( V[0, 2],   V[0, 2 − 2] + 1 ) = max(0,   0 + 1) = 1.
  • For w = 3 to 8: Knapsack has at least 2 kg capacity, so we can take Object 1:
    V[1, w] = max( V[0, w],   V[0, w − 2] + 1 ) = max(0,   0 + 1) = 1 for all remaining columns.
Row 1 Result: [0, 0, 1, 1, 1, 1, 1, 1, 1]

Step 2: Filling Row i = 2 (Object 2: w₂ = 3, p₂ = 2)

w₂ = 3, p₂ = 2
  • For w = 1 and w = 2: w₂ = 3 > w, Object 2 cannot fit. Copy from above: V[2, 1] = V[1, 1] = 0 and V[2, 2] = V[1, 2] = 1.
  • For w = 3: Object 2 fits!
    V[2, 3] = max( V[1, 3],   V[1, 3 − 3] + 2 ) = max(1,   0 + 2) = 2.
  • For w = 4:
    V[2, 4] = max( V[1, 4],   V[1, 4 − 3] + 2 ) = max(1,   V[1, 1] + 2) = max(1,   0 + 2) = 2.
  • For w = 5: Knapsack has 5 kg! We can fit both Object 1 (2 kg) and Object 2 (3 kg):
    V[2, 5] = max( V[1, 5],   V[1, 5 − 3] + 2 ) = max(1,   V[1, 2] + 2) = max(1,   1 + 2) = 3.
  • For w = 6, 7, 8: With only objects 1 and 2 available (combined weight = 2 + 3 = 5 kg), maximum profit remains:
    V[2, w] = max(1,   1 + 2) = 3.
Row 2 Result: [0, 0, 1, 2, 2, 3, 3, 3, 3]

Step 3: Filling Row i = 3 (Object 3: w₃ = 4, p₃ = 5)

w₃ = 4, p₃ = 5
  • For w = 1, 2, 3: w₃ = 4 > w, Object 3 cannot fit. Copy from above: V[3, 1] = 0, V[3, 2] = 1, V[3, 3] = 2.
  • For w = 4: Object 3 fits alone (wt 4, profit 5):
    V[3, 4] = max( V[2, 4],   V[2, 4 − 4] + 5 ) = max(2,   0 + 5) = 5.
  • For w = 5 (V[3, 5]):
    V[3, 5] = max( V[2, 5],   V[2, 5 − 4] + 5 ) = max(3,   V[2, 1] + 5) = max(3,   0 + 5) = 5.

    💡 What does this mean in simple terms? In a 5 kg bag with the first 3 items: Option 1 (skip Obj 3) gave profit 3 (carrying Obj 1 + Obj 2). Option 2 (take Obj 3) gives profit 5 (carrying Obj 3 alone). Since $5 > $3, we choose 5!

  • For w = 6: Fits Object 3 (4 kg) + Object 1 (2 kg):
    V[3, 6] = max( V[2, 6],   V[2, 6 − 4] + 5 ) = max(3,   V[2, 2] + 5) = max(3,   1 + 5) = 6.
  • For w = 7: Fits Object 3 (4 kg) + Object 2 (3 kg):
    V[3, 7] = max( V[2, 7],   V[2, 7 − 4] + 5 ) = max(3,   V[2, 3] + 5) = max(3,   2 + 5) = 7.
  • For w = 8:
    V[3, 8] = max( V[2, 8],   V[2, 8 − 4] + 5 ) = max(3,   V[2, 4] + 5) = max(3,   2 + 5) = 7.
Row 3 Result: [0, 0, 1, 2, 5, 5, 6, 7, 7]

Step 4: Filling Row i = 4 (Object 4: w₄ = 5, p₄ = 6)

w₄ = 5, p₄ = 6
  • For w = 1, 2, 3, 4: w₄ = 5 > w, Object 4 cannot fit. Copy directly from row 3: V[4, 1] = 0, V[4, 2] = 1, V[4, 3] = 2, V[4, 4] = 5.
  • For w = 5: Object 4 fits alone (wt 5, profit 6):
    V[4, 5] = max( V[3, 5],   V[3, 5 − 5] + 6 ) = max(5,   0 + 6) = 6.
  • For w = 6:
    V[4, 6] = max( V[3, 6],   V[3, 6 − 5] + 6 ) = max(6,   V[3, 1] + 6) = max(6,   0 + 6) = 6.
  • For w = 7: Fits Object 4 (5 kg) + Object 1 (2 kg):
    V[4, 7] = max( V[3, 7],   V[3, 7 − 5] + 6 ) = max(7,   V[3, 2] + 6) = max(7,   1 + 6) = 7.
  • For w = 8: Knapsack has 8 kg! Fits Object 4 (5 kg) + Object 2 (3 kg):
    V[4, 8] = max( V[3, 8],   V[3, 8 − 5] + 6 ) = max(7,   V[3, 3] + 6) = max(7,   2 + 6) = 8!
Row 4 Result: [0, 0, 1, 2, 5, 6, 6, 7, 8]  →  Optimal Profit = $8

🔍 3. Backtracking: Which Objects are in the Bag?

Our table gave us the maximum profit: $8 (at cell V[4, 8]). But which objects did we actually put in the bag?

💡 Simple Rule: Look at the number directly above!

Just ask: "Did the profit change compared to the row above?"

1. If numbers are DIFFERENT:

👉 YES, item is inside the bag! (x = 1)
Subtract its weight from your remaining bag space.

2. If numbers are the SAME:

👉 NO, item is NOT in the bag. (x = 0)
Bag space stays exactly the same.

Step 1 Start at the bottom-right corner: V[4, 8] = 8

Look at the cell directly above it: V[3, 8] = 7.
• Are they different? Yes (8 ≠ 7). The profit jumped because we took Object 4!
• Decision: x₄ = 1 (Object 4 is IN the bag)
• Bag space left: 8 kg − 5 kg = 3 kg. Now check row 3 at column 3.

Step 2 Check Row 3 at 3 kg space: V[3, 3] = 2

Look at the cell directly above it: V[2, 3] = 2.
• Are they different? No (2 == 2). The profit didn't change, so Object 3 was not used.
• Decision: x₃ = 0 (Object 3 is NOT in the bag)
• Bag space left: Still 3 kg. Now check row 2 at column 3.

Step 3 Check Row 2 at 3 kg space: V[2, 3] = 2

Look at the cell directly above it: V[1, 3] = 1.
• Are they different? Yes (2 ≠ 1). The profit jumped from 1 to 2 because we took Object 2!
• Decision: x₂ = 1 (Object 2 is IN the bag)
• Bag space left: 3 kg − 3 kg = 0 kg. Bag is now full!

Step 4 Check Object 1: 0 kg space left

• Bag has 0 kg space left, so Object 1 cannot fit.
• Decision: x₁ = 0 (Object 1 is NOT in the bag).

🎯 Final Computed Solution

Verified Match
Decision Vector X = (0, 1, 0, 1)
Included Items Object 2 & Object 4
Maximum Profit Z = 2 + 6 = $8

Sets Method (Tuple Generation & Dominance Rule)

Alternative Dynamic Programming Technique using Ordered Pairs (Profit, Weight)

Tab 3 • Sets Method

📦 1. Concept Overview: Ordered Pairs (Profit, Weight)

Instead of constructing an (n + 1) × (M + 1) 2D grid, the Sets Method generates a progressive sequence of sets containing ordered pairs:

S₀,   S₁,   S₂,   S₃,   ...   Sₙ

Each element in a set is an ordered pair: (Profit, Weight) = (P, w).

📌 The Two-Step Set Generation Process:
  • Initial Base Set: Start with no items chosen: S₀ = {(0, 0)}.
  • Step 1 (Generate Included Set Si−1¹): Add (Pi, wi) to every tuple in Si−1:
    Si−1¹ = Si−1 + (Pi, wi) = { (p + Pi,   w + wi)  |  (p, w) ∈ Si−1 }
  • Step 2 (Merge & Filter): Form Si by merging Si−1 (exclude item i) and Si−1¹ (include item i), while applying the two filtering rules below.
Filter Rule 1

Capacity Limit (Weight ≤ M)

Discard any tuple whose total weight exceeds the knapsack capacity:

If w > M (here w > 8) → DISCARD

Knapsack cannot physically hold objects exceeding 8 kg.

Filter Rule 2

Dominance Rule (Optimality Pruning)

If a choice exists that yields less profit with equal/more weight, prune it:

If p₁ ≤ p₂ and w₁ ≥ w₂ → Prune (p₁, w₁)

Why carry less profit with more weight? Pruning prevents combinatorial explosion.

📝 2. Step-by-Step Set Generation (Forward Step)

Given: M = 8, P = {1, 2, 5, 6}, W = {2, 3, 4, 5}

Initial State (0 Objects Considered):

Base Set

No items taken → Profit = 0, Weight = 0:

S₀ = { (0, 0) }

Item 1: Profit P₁ = 1, Weight w₁ = 2

Include / Exclude Item 1
  • Include Item 1: Add (1, 2) to each tuple in S₀: S₀¹ = { (0+1, 0+2) } = { (1, 2) }
  • Merge: Combine S₀ and S₀¹:
S₁ = { (0, 0),   (1, 2) }

Item 2: Profit P₂ = 2, Weight w₂ = 3

Include / Exclude Item 2
  • Include Item 2: Add (2, 3) to each tuple in S₁: S₁¹ = { (0+2, 0+3), (1+2, 2+3) } = { (2, 3), (3, 5) }
  • Merge: Combine S₁ and S₁¹:
S₂ = { (0, 0),   (1, 2),   (2, 3),   (3, 5) }

All weights ≤ 8. Pairs are strictly sorted by increasing weight & profit.

Item 3: Profit P₃ = 5, Weight w₃ = 4 (Pruning Occurs Here!)

Capacity & Dominance Filtering
  • Include Item 3: Add (5, 4) to each tuple in S₂:
    S₂¹ = { (0+5, 0+4),   (1+5, 2+4),   (2+5, 3+4),   (3+5, 5+4) }
         = { (5, 4),   (6, 6),   (7, 7),   (8, 9) }
  • ❌ Capacity Limit Pruning: Discard (8, 9) because weight 9 > 8 kg (knapsack capacity exceeded).
  • ⚡ Dominance Rule Pruning: Compare (3, 5) ∈ S₂ with (5, 4) ∈ S₂¹:
    • Pair (5, 4) gives Profit = 5 with Weight = 4.
    • Pair (3, 5) gives only Profit = 3 with Weight = 5.
    👉 (3, 5) has LESS profit and MORE weight! Therefore, (3, 5) is strictly DOMINATED and pruned!
  • Merge Remaining Pairs:
S₃ = { (0, 0),   (1, 2),   (2, 3),   (5, 4),   (6, 6),   (7, 7) }

Item 4: Profit P₄ = 6, Weight w₄ = 5 (Final Set)

Final Pruning
  • Include Item 4: Add (6, 5) to each tuple in S₃:
    S₃¹ = { (0+6, 0+5),   (1+6, 2+5),   (2+6, 3+5),   (5+6, 4+5),   (6+6, 6+5),   (7+6, 7+5) }
         = { (6, 5),   (7, 7),   (8, 8),   (11, 9),   (12, 11),   (13, 12) }
  • ❌ Capacity Limit Pruning: Discard (11, 9), (12, 11), and (13, 12) because their weights (9, 11, 12) exceed 8 kg.
  • ⚡ Dominance Rule & Duplicates Pruning:
    • Compare (6, 6) ∈ S₃ with (6, 5) ∈ S₃¹: Both give Profit = 6, but (6, 5) has less weight (5 < 6). So (6, 6) is dominated and pruned!
    • (7, 7) appears in both S₃ and S₃¹ (duplicate, keep one instance).
  • Final Merged & Pruned Set:
S₄ = { (0, 0),   (1, 2),   (2, 3),   (5, 4),   (6, 5),   (7, 7),   (8, 8) }

🔍 3. Backtracking to Find Included Items (Backward Step)

The highest profit in the final set S₄ within knapsack capacity 8 is the last pair: (8, 8) → Profit = 8, Weight = 8.

To discover which items generated this optimal tuple, we trace backward through our sets:

Step 1: Check Item 4 (P₄ = 6, w₄ = 5) x₄ = 1

• Is (8, 8) present in S₃? No.
• Since (8, 8) did not exist in S₃, it must have been generated by including Item 4!
• Decision: x₄ = 1 (Item 4 is INCLUDED).
• Subtract Item 4 values from (8, 8): (8 − 6,   8 − 5) = (2, 3). Next search pair is (2, 3).

Step 2: Check Item 3 (P₃ = 5, w₃ = 4) x₃ = 0

• Look for pair (2, 3).
• Is (2, 3) present in S₃? Yes.
• Is (2, 3) already present in S₂? Yes.
• Because (2, 3) was already achieved in S₂ without Item 3, Item 3 was NOT needed.
• Decision: x₃ = 0 (Item 3 is EXCLUDED).
• Search pair remains (2, 3).

Step 3: Check Item 2 (P₂ = 2, w₂ = 3) x₂ = 1

• Look for pair (2, 3).
• Is (2, 3) present in S₁? No (S₁ only contains (0, 0) and (1, 2)).
• Since (2, 3) did not exist in S₁, it was generated by including Item 2!
• Decision: x₂ = 1 (Item 2 is INCLUDED).
• Subtract Item 2 values from (2, 3): (2 − 2,   3 − 3) = (0, 0). Next search pair is (0, 0).

Step 4: Check Item 1 (P₁ = 1, w₁ = 2) x₁ = 0

• Pair (0, 0) is present in both S₁ and S₀.
• Decision: x₁ = 0 (Item 1 is EXCLUDED).

🎯 Final Sets Method Result

Matches Tabular Method!
Decision Vector (x₁, x₂, x₃, x₄) = (0, 1, 0, 1)
Included Items Item 2 & Item 4
Max Profit & Total Weight Profit = $8,   Weight = 8 kg

⚖️ 4. Comparison: Tabular Method vs. Sets Method

Feature Method 1: Tabular Method Method 2: Sets Method
Data Structure 2D Matrix V[n+1][M+1] Dynamic List of Ordered Pairs (P, w)
Space Complexity O(n × M) O(2ⁿ) worst-case, far less in practice due to dominance pruning
When Best Used When capacity M is small/moderate When capacity M is huge (e.g. 10⁶) but n is small
Pruning Mechanism Evaluates every integer capacity 0 to M Prunes dominated & overweight pairs immediately
