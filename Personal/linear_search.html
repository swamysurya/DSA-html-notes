What is Linear Search?

**Linear Search** is the most straightforward search method. It sequentially scans a collection element-by-element from the beginning (index 0) to the end (index N-1) until the target key is located or the collection is exhausted.

🔑 Key Attributes

  • Unsorted Collections: Ideal choice since it does not require elements to be ordered.
  • Memory Layout: Works on array-based and linked structures (like singly or doubly linked lists) since it only requires sequential pointer traversal.
  • Sentinel optimization: We can avoid index boundary comparisons (`i < N`) on every loop iteration by inserting the target key as a sentinel element at the end of the array.

Sentinel Search Variation

In a traditional linear search loop, we check: if (i < N && arr[i] == target) By setting the last element to the target key, we can remove the `i < N` check, saving one comparison instruction per step in the assembly code.

Conceptual Scan Step: Inspections move sequentially left-to-right.

Step 1: Inspect Index 0

Comparison: `arr[0]` (12) != 25. Move pointer to next index.

Step 2: Inspect Index 1

Comparison: `arr[1]` (5) != 25. Move pointer to next index.

Step 3: Inspect Index 2

Comparison: `arr[2]` (25) == 25. Match found! Stop search.

Linear Search Complexity Analysis

Page 3

Asymptotic Runtime Bounds

Case Scenario Time Complexity
Best Case Target element is at index 0. Requires exactly 1 comparison. O(1)
Average Case Target is located in the middle of the collection. Requires N/2 comparisons. O(N)
Worst Case Target element is at index N-1, or not present at all. Requires N comparisons. O(N)

📝 Space Complexity:

Linear search performs lookup **in-place** using a single index counter. No extra memory is allocated:
Space Complexity = O(1) (Constant space)
