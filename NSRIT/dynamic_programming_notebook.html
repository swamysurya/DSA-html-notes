1. What is Dynamic Programming?

Dynamic Programming (DP) solves complex problems by combining the solutions to overlapping sub-problems. It is primarily used for optimization problems (minimization or maximization).

In dynamic programming, each sub-problem solution contains a concrete value. Instead of re-computing the same sub-problem again and again, dynamic programming follows three systematic steps:

Core Steps of Dynamic Programming:

  1. Decomposition: It breaks the complex problem into simple sub-problems.
  2. Optimal Substructure: It finds optimal solutions to these sub-problems.
  3. Storage (Memoization): It stores the result of sub-problems in memory (table/array). The process of storing sub-problems is known as memoization.

Problem Decomposition & Memoization Flow

Large problems are broken into smaller sub-problems. Once solved, sub-problem solutions are saved in the lookup table (memo table) to avoid redundant recalculation.

2. Intuitive Example: Summation & Repeated Work (The Essence of DP)

Dynamic Programming (DP) can feel abstract at first, but its core principle is remarkably simple: "Remember answers to sub-problems you have already solved, so you never waste time recalculating them."

📝

The Classic "Paper Test" Intuition

Imagine a professor writes the following question on a sheet of paper and asks a student:

Step 1: The Initial Problem
1 + 1 + 1 + 1 + 1 = ?

The student counts the ones: "1, 2, 3, 4, 5."
Student answers: 5.

Step 2: Append One More Number
1 + 1 + 1 + 1 + 1 + 1 = ?

The student answers instantly without hesitation: 6!

The Core Question: How did the student know the answer was 6 in less than a second? Did they recount all six 1s from left to right? No!
The student remembered that the previous part (1 + 1 + 1 + 1 + 1) was already evaluated to 5. They simply performed: 5 + 1 = 6.
👉 This is exactly what Dynamic Programming does: caching past computations to solve future problems in O(1) time!

Repeated Sub-expression Evaluation

Consider evaluating three separate queries or expressions that share a common heavy sub-sum:

Query 1
(1 + 2 + 3 + 5) + 4
Query 2
(1 + 2 + 3 + 5) + 9
Query 3
(1 + 2 + 3 + 5) × 10
❌ Without DP (Naive Recomputation)
  • Query 1 computes: 1 + 2 = 3 → 3 + 3 = 6 → 6 + 5 = 11 (3 additions)
  • Query 2 re-computes: 1 + 2 = 3 → 3 + 3 = 6 → 6 + 5 = 11 (3 additions)
  • Query 3 re-computes: 1 + 2 = 3 → 3 + 3 = 6 → 6 + 5 = 11 (3 additions)
  • Total: 9 additions performed repeatedly for the identical sub-term!
✅ With DP (Memoization / Caching)
  • Query 1 computes (1 + 2 + 3 + 5) = 11 once and saves: Memo["1+2+3+5"] = 11.
  • Query 2 looks up cached value: 11 + 9 = 20 in O(1) time!
  • Query 3 looks up cached value: 11 × 10 = 110 in O(1) time!
  • Total: Only 3 additions once + instant O(1) lookups!

3. Major Applications of Dynamic Programming

Dynamic Programming is applied to several seminal problems in computer science and algorithmic graph theory:

1. All Pairs Shortest Path
Floyd-Warshall Algorithm

Computes shortest paths between every pair of vertices in O(V³) time using matrix transitions.

2. Single Source Shortest Path
Bellman-Ford Algorithm

Finds shortest paths from a single source even with negative weight edges, detecting negative cycles.

3. Optimal Binary Search Tree
OBST Dynamic Programming

Arranges keys based on search probabilities to minimize overall search cost.

4. 0/1 Knapsack Problem
Indivisible Items Packing

Maximizes profit under weight capacity W where items cannot be divided.

5. Travelling Salesperson Problem
TSP (Held-Karp Algorithm)

Finds the minimum cost Hamiltonian cycle visiting each city once using subset states.

6. Sequence Alignment & LCS
Longest Common Subsequence

Used extensively in computational biology, diff engines, and string metrics.

1. Single-Source Shortest Path (SSSP) Problem

Given a directed, weighted graph G = (V, E) and a designated source vertex s, the Single-Source Shortest Path (SSSP) problem determines the minimum path cost from s to every other vertex v ∈ V.

💡 Why Dynamic Programming for SSSP?
  • Handles Negative Edge Weights: Unlike Dijkstra's greedy strategy which makes premature choices and fails on negative edges, Dynamic Programming systematically examines every candidate path.
  • Optimal Substructure: A shortest path from source s to destination v through predecessor u contains within it the optimal shortest subpath from s to u.
  • Overlapping Subproblems: Shortest paths with at most k edges are computed directly by extending precomputed shortest paths of at most k - 1 edges.

📌 Fundamental Relaxation Rules

Core Algorithm Rules

Step 1: Go on relaxation of all the edges (n - 1) times (where n = |V| vertices).

Relaxation Condition:
if   d(u) + c(u, v) ≤ d(v)
then   d(v) = d(u) + c(u, v)

Notation: d(u) = current distance to node u,  c(u, v) = cost/weight of directed edge (u, v),  d(v) = updated distance to node v.

3. Complexity & Summary

⏱️ Complexity Analysis
  • Outer Loop: Runs n - 1 iterations (passes).
  • Inner Loop: Relaxes all m = |E| edges once per pass.
  • Total Time Complexity: O(V · E) = O(n · m).
  • For dense graphs where m = O(n2), time complexity is O(n3).
  • Space Complexity: O(n) to maintain the distance array d[].
🚨 Negative Cycle Detection

After n - 1 passes, perform one additional pass over all edges:

if d(u) + c(u, v) < d(v) → Negative Cycle Exists!

If any distance can still decrease, a negative-weight cycle is reachable, which would make shortest paths infinitely negative.

1. Floyd-Warshall Algorithm Concept

The Floyd-Warshall algorithm is a dynamic programming algorithm used to compute all-pairs shortest paths in a directed or undirected weighted graph, where V is the number of vertices in the graph.

  • The algorithm finds the shortest paths between all pairs of vertices in a given weighted graph.
  • It generates a sequence of distance matrices A0, A1, A2, ..., AV representing the minimum distance from any node i to any other node j using intermediate vertices up to k.

Step-by-Step Algorithm:

Step 1: Remove all self-loops and parallel edges from the graph. (In standard test graphs, there are neither self-loops nor parallel edges).

Step 2: Write the initial distance matrix A0:

  • It represents the distance between every pair of vertices in the form of given edge weights.
  • For diagonal elements: distance value = 0 (i.e. distance from node to itself).
  • For vertices having a direct edge between them: distance value = weight of that edge.
  • For vertices having no direct edge between them: distance value = ∞.

Step 3: Using the Floyd-Warshall DP recurrence, compute the subsequent matrices A1, A2, ..., AV sequentially.

Floyd-Warshall Recurrence Formula
Ak[i, j] = min { Ak-1[i, j],   Ak-1[i, k] + Ak-1[k, j] }
Where k represents the intermediate vertex candidate. For matrix Ak, row k and column k remain unchanged from Ak-1.

Travelling Salesperson Problem (TSP)

Page 4

1. Problem Formulation & Recurrence

The Travelling Salesperson Problem (TSP) aims to find the minimum cost Hamiltonian cycle starting from a designated vertex (e.g. vertex A), visiting every other vertex in the graph exactly once, and returning to the starting point.

DP Formulation (Held-Karp Recurrence):
g(i, S) = minj ∈ S { w(i, j) + g(j, S \ {j}) }

Where g(i, S) is the length of the shortest path starting at vertex i, visiting all vertices in subset S in any order, and terminating at the origin vertex A.
Base Case: g(j, ∅) = w(j, A) (cost of returning back to the start node A).

Subproblem State Tree Breakdown

2. Step-by-Step Calculation Trace

To find the minimum tour cost starting from vertex A visiting {B, C, D}:

Top-Level Expansion:
g(A, {B, C, D}) = min {
• w(A, B) + g(B, {C, D}) = 16 + ?
• w(A, C) + g(C, {B, D}) = 11 + ?
• w(A, D) + g(D, {B, C}) = 6 + ?
}
Bottom-Up Sub-Problem Computations:
Base Return Steps: • g(C, {D}) = w(C, D) + g(D, {∅})
            = 14
Alternative Branch: • g(D, {C}) = w(D, C) + g(C, {∅})
            = 2 + 4 = 6
Evaluating Subproblem g(B, {C, D}):
• Branch 1 via C: w(B, C) + g(C, {D}) = 13 + 14 = 27
• Branch 2 via D: w(B, D) + g(D, {C}) = 16 + 6 = 22
∴ g(B, {C, D}) = min { 27, 22 } = 22
🏆 Final Optimal Tour Evaluation:

g(A, {B, C, D}) = min ( w(A, B) + g(B, {C, D}) ) = 16 + 22 = 38

The overall shortest Hamiltonian cycle starting and ending at city A has a minimal cost of 38.

Optimal Binary Search Tree (OBST)

Page 5

1. Problem Definition & Formulation

The Optimal Binary Search Tree (OBST) problem is a classic dynamic programming problem. It involves constructing a binary search tree from a given sequence of sorted keys and access frequencies such that the total expected search cost is minimized.

Given Inputs:
  • A sorted set of keys (k1, k2, ..., kn)
  • A set of access frequencies/probabilities (f1, f2, ..., fn) for each key
  • A set of internal node costs (c1, c2, ..., cn)
Dynamic Programming Recurrence:
cost[i, j] = mini ≤ k ≤ j { cost[i, k-1] + cost[k+1, j] + sum(frequencies[i ... j]) }

Where i and j are the boundary indices of the sub-tree, k is the index of the chosen root node, and sum(frequencies[i ... j]) is the sum of frequencies of all keys in the sub-tree.
The minimum cost of searching for the entire tree is stored in cost[1, n].

0/1 Knapsack Problem

Page 6

1. Problem Overview & Dynamic Programming

The 0/1 Knapsack algorithm is a dynamic programming approach where items are either completely included (1) or not included at all (0).

Core Rules:
  1. Items are indivisible: we cannot take a fraction of any item (unlike the Fractional Knapsack problem).
  2. For each item, we make a binary choice: either include it completely or leave it completely.
  3. We must maximize total profit subject to total weight ≤ W.

Algorithm Execution Steps:

Step 1: Draw a 2D table T with (n + 1) rows and (W + 1) columns.

Step 2: Fill all boxes of the 0th row and 0th column with 0s (base case: 0 items or 0 capacity gives 0 value).

Step 3: Fill the table row-wise from top to bottom, left to right using the dynamic programming recurrence:

T[i, j] = max { T[i-1, j],   valuei + T[i-1, j - weighti] }

Here T[i, j] is the maximum value obtainable using a subset of items {1, ..., i} within weight limit j.

Finding the Included Items (Backtracking):

Once the table is completely filled, the value of the last cell T[n, W] represents the maximum possible total profit.

  1. Look at the last column of the table at cell T[n, W].
  2. Start scanning the entries from bottom to top.
  3. On encountering an entry whose value is not the same as the value stored immediately above it (T[i, j] ≠ T[i-1, j]), mark item i as included!
  4. Reduce remaining weight capacity j ← j - weighti, move to row i - 1, and continue until row 0.
