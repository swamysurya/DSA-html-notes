What is std::unordered_map?

In C++, std::unordered_map is an associative container that stores key-value pairs in an unsorted hash table. It provides extremely fast average search, insert, and delete operations.

🔑 Hashing & Chaining Architecture

The keys are hashed to assign them to specific buckets, and collisions are resolved using **Chaining**:

  1. Hashing the Key: The key's hash value determines the bucket index: index = hash(key) % buckets.
  2. List of Pairs: Each bucket contains a singly linked list storing the key-value pair nodes (`std::pair`).
  3. Load Factor Threshold: If elements exceed the bucket count (Load Factor > 1.0), the container triggers a rehash to restore O(1) performance.

Comparison: Map vs Unordered Map

  • std::map: Guarantees O(log N) worst-case. Keys are stored sorted.
  • std::unordered_map: Fast O(1) average lookup, but O(N) worst-case (if all keys collide). Elements are unsorted.
Conceptual Bucket Map Chaining: Singly linked list chains contain Key:Value nodes.

Let us trace inserting key-value pairs {10: "X"}, {5: "Y"}, {12: "Z"} into a hash map of **5 buckets** using `hash(key) = key`.

Step 1: Empty Hash Table

Empty bucket index arrays initialized to NIL.

Step 2: Insert {10: "X"}

• 10 % 5 = 0. Node `{10: "X"}` is placed at bucket 0.

Step 3: Insert {5: "Y"} (Collision!)

• 5 % 5 = 0. Collision at bucket 0! `{5: "Y"}` is inserted at the head of the chain.

Step 4: Insert {12: "Z"}

• 12 % 5 = 2. Pair `{12: "Z"}` is inserted at bucket 2.

Unordered Map Methods & Complexity Analysis

Page 3

Primary std::unordered_map Operations

Method Description Average Time Worst-Case Time
insert({key, val}) Hashes key and inserts pair in bucket list. O(1) O(N) (rehash)
erase(key) Removes the pair corresponding to the key. O(1) O(N)
find(key) Finds pair by key. Returns iterator or `end()`. O(1) O(N)
operator[key] Returns value associated with key. Updates if exists. O(1) O(N)

📝 Time Complexity Explanations:

  • Average Case O(1): Achieved by uniform distribution of hash keys. Chain lengths stay bounded (Load Factor ≤ 1.0).
  • Worst Case O(N): Degenerates if all keys hash to the same bucket index, turning search into a linear linked list scan.
