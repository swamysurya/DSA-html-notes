Ordered Set Concepts & Red-Black Trees

Page 1

What is std::set?

In C++, std::set is an associative container that stores unique elements in a strict sorted order (by default, ascending order). Unlike std::unordered_set (which uses a Hash Table), the ordered set is implemented using a Red-Black Tree under the hood.

🌳 Under-the-Hood Data Structure: Red-Black Tree

A Red-Black Tree is a self-balancing Binary Search Tree (BST). Each node in the tree stores a key, pointers to left/right children, and a **color attribute** (Red or Black). The tree balances itself during inserts/deletions by enforcing 5 strict properties:

  1. Node Color: Every node is either Red or Black.
  2. Root Property: The Root node is always Black.
  3. Leaf Property: Every leaf node (NIL/null pointer) is considered Black.
  4. Red Violation Rule: If a node is Red, then both of its children must be Black (no consecutive red nodes allowed).
  5. Black Height Property: For each node, all simple paths from the node to descendant leaves contain the same number of Black nodes.

Why Use a Self-Balancing Tree?

In a standard BST, if elements are inserted in a sorted sequence (e.g., 10, 20, 30, 40), the tree becomes a skewed linear chain. The search complexity degrades to O(N).

Red-Black Tree properties guarantee that the longest path from root to leaf is no more than twice as long as the shortest path. This ensures that the tree height remains logarithmic: Height ≤ 2 × log2(N + 1), maintaining strict O(log N) lookup, insert, and delete operations.

Standard Red-Black Tree Structure: Leaves are NIL nodes. Red nodes cannot have red children.

Step-by-Step BST Balancing & Rotations

Page 2

Let us trace the step-by-step insertion of values 10, 20, 30 in sorted sequence into an empty std::set. We will watch how a double-red violation is resolved using a **Left Rotation** and **Recoloring**.

Step 1: Insert 10

• The tree is empty. 10 is inserted as the root node.
• By Property 2, the root must be recolored Black.

Step 2: Insert 20

• 20 is greater than 10, so it goes to the right child slot.
• Newly inserted nodes are colored Red. No properties are violated.

Step 3: Insert 30 (Violation!)

• 30 goes to the right child of 20, colored Red.
• Violation: Node 20 and node 30 are consecutive red nodes (violates Property 4).
• Since the uncle node (left child of 10) is NIL (Black) and 30 is an outer grandchild, we require a Left Rotation at grandparent 10.

Step 4: Rotate & Recolor (Balanced)

• We perform a **Left Rotation** around parent 10: 20 moves up to become parent, 10 moves down to become left child of 20.
• **Recoloring:** The new parent (20) is colored Black, and its children (10, 30) are colored Red.
• All Red-Black Tree properties are now satisfied!

STL Methods & Complexity Analysis

Page 3

Primary std::set Operations

Method Description Average Time Worst-Case Time
insert(val) Inserts the value in sorted position. Checks for duplicates. O(log N) O(log N)
erase(key) Removes the element matching the key, triggers rebalance. O(log N) O(log N)
find(key) Searches the key using BST traversal. Returns iterator. O(log N) O(log N)
lower_bound(k) Returns iterator to the first element that is ≥ k. O(log N) O(log N)
upper_bound(k) Returns iterator to the first element that is > k. O(log N) O(log N)
size() Returns total number of elements in the tree. O(1) O(1)

📝 Rationale behind complexities:

  • Guaranteed Logarithmic Heights: Because of the Red-Black Tree constraints, the height is mathematically capped. Even in the worst-case configuration, operations are guaranteed to visit no more than 2 × log2(N) levels.
  • Comparison to std::unordered_set:
    • `unordered_set` has a faster average case (O(1)) but a degraded worst-case (O(N)).
    • `std::set` has a slightly slower average case (O(log N)) but guarantees O(log N) worst-case performance, making it highly predictable for real-time systems.
    • `std::set` keeps keys sorted, which is necessary for range queries (`lower_bound` / `upper_bound`), while `unordered_set` has arbitrary order.
