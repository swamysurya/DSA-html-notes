1. What is Branch and Bound? Foundations & Optimization

Problem-solving strategy for optimization, state-space trees, cost bounds, and paradigm contrast with Backtracking.

Tab 1 • Core Principles

§1. What is Branch and Bound?

Branch and Bound (B&B) is a problem-solving strategy specifically designed to solve optimization problems.

"Generate possible solutions, calculate their costs or bounds, and intelligently decide which solution or branch should be explored next."

It shares architectural roots with Backtracking because both paradigms organize and traverse candidates using a State Space Tree. However, Branch and Bound differs dramatically in how it explores that State Space Tree and decides which node to visit next.

💡 Why Use Branch and Bound?

When an optimization search space contains thousands or millions of possible candidate combinations, pure brute force is impossible. Branch and Bound equips us to locate the globally best possible solution without necessarily examining every single leaf.

§2. What are Optimization Problems?

An optimization problem is any problem where:

"There are multiple possible (feasible) solutions, and we want to find the best one according to a specified objective function."

For example, suppose we have several available jobs and we want to pick a subset that yields the maximum profit:

Feasible Combinations:
  • {Job 1}
  • {Job 2}
  • {Job 1, Job 3}
  • {Job 2, Job 4}
  • {Job 1, Job 2, Job 4}
  • ... many more

All of these are mathematically valid combinations, but we don't want just any solution—we want the best solution. That is the definition of an optimization problem!

§3. Minimization Problem

Goal: Find the candidate having the smallest possible value.

Route A → ₹500
Route B → ₹350 ← Minimum (Optimal)
Route C → ₹450
Real-World Examples:
  • Minimum travel distance (TSP / Shortest Path)
  • Minimum task execution time / Latency
  • Minimum financial operational cost
  • Minimum hardware / server resource allocation
Minimization = Find the smallest / cheapest value.

§4. Maximization Problem

Goal: Find the candidate having the largest possible value.

Solution A → Profit = ₹500
Solution B → Profit = ₹800 ← Maximum (Optimal)
Solution C → Profit = ₹650
Real-World Examples:
  • Maximum net investment profit (Knapsack)
  • Maximum corporate revenue & throughput
  • Maximum utility score / value delivery
  • Maximum schedulable jobs completed
Maximization = Find the largest / highest value.

§5. Minimization vs Maximization

Type Goal Example
Minimization Find the smallest value Minimum cost, shortest route, minimum time
Maximization Find the largest value Maximum profit, maximum revenue

In computer science discussions, Branch and Bound is explained primarily for minimization problems.

If we ever have a maximization problem (such as maximizing total profit), we can easily convert it into an equivalent minimization problem (for example, by minimizing negative profit: Cost = -Profit). We will see this in action in our upcoming example!

§6. What is a State Space Tree?

A State Space Tree is an organized n-ary tree that represents all the possible states, choices, or decision sequences of a computational problem.

"Think of it as a Tree of Decisions. Every node represents a specific partial or complete state of the solution. Every downward edge represents a decision made at that juncture."

A path traced from the root to any intermediate node represents the series of decisions made so far. Both Backtracking and Branch and Bound utilize State Space Trees to represent candidate spaces.

§7. What is a Cost Function?

A cost function is a function that calculates a numerical value representing the cost or quality of a particular node or solution state.

The exact meaning of "cost" depends on the problem we are solving:

  • In a shortest-path problem → cost may represent distance.
  • In a scheduling problem → cost may represent time.
  • In a resource allocation problem → cost may represent resource usage.

🎯 The Core Question Answered by the Cost Function:

"Which node should we explore next?"
Why is the cost function relevant?

Without a cost function, we have no way to determine which node is more promising in Least Cost Branch and Bound. The cost function provides the numerical value that allows us to compare candidate nodes fairly.

💡 Note: We will see exactly how costs are calculated and compared with real numbers step-by-step in our upcoming Job Sequencing example in Tab 2 and Tab 3!

§41. Paradigm Contrast: Branch and Bound vs. Backtracking

State Space Tree
  ↓
Depth First Search (DFS)
  ↓
Plunge deeply along one path
  ↓
If constraint violated → Backtrack immediately

Best for decision and feasibility problems (e.g. N-Queens, Sudoku). Memory footprint is minimal (O(d) stack).

⚖️ Branch & Bound Search Flow

State Space Tree
  ↓
Generate all candidate children
  ↓
Choose next node via strategy (FIFO / LIFO / LC)
  ↓

Best for global optimization problems (e.g. 0/1 Knapsack, TSP, Job Sequencing).

§8. Introduction: Job Sequencing with Deadlines Across 3 Paradigms

The problem before us is Job Sequencing with Deadlines. In computer science and algorithm design, this famous problem can actually be approached using three distinct algorithmic paradigms:

1. Greedy Method

Highly efficient when all jobs take identical unit processing time (1 hour each). Sorts by profit and places into the latest free slot.

2. Dynamic Programming

Solves via overlapping subproblems and memoization, finding exact optimal subsets by evaluating state transitions.

3. Branch and Bound

Explores the State Space Tree while using rigorous mathematical bounds to prune unpromising branches early.

"Even this problem can be solved using greedy method and dynamic programming. But let us learn how it can be solved using Branch and Bound."

§9. The Cardinal Rule: Branch & Bound Solves Minimization Problems

Before writing a single formula or building the tree, there is one fundamental property of Branch and Bound we must remember:

⚠️ The Crucial Principle:

Branch and Bound is useful for solving MINIMIZATION problems. It cannot directly solve MAXIMIZATION problems.

If you already know the standard Job Sequencing with Deadlines problem, it is naturally a maximization problem: profits are assigned to each job, and we want to select jobs that yield the maximum possible profit. Because Branch and Bound minimizes cost bounds, we cannot apply it directly to a raw profit-maximization objective without adaptation.

§10. Transforming the Problem: Instead of Profit, Take Penalty

How do we turn a maximization problem into a minimization problem? We perform a simple and elegant conceptual transformation:

"So we have converted the problem: instead of profit, we are taking penalty here. Penalty means we have to pay — right? We will not gain, but we will lose. So instead of profit, we are calling it as penalty."

What is Penalty?

If we fail to finish a job within its designated deadline, we suffer a financial loss or fine. That loss is called the penalty (pi).

The Equivalence Rule

Selecting jobs to complete within their deadlines such that the total penalty paid is minimized automatically means the total profit earned is maximized!

∴ Minimizing Total Penalty Paid ≡ Maximizing Total Profit Retained

§11. Key Assumption: Varying Completion Times (ti ≠ 1)

Notice another critical detail that makes this problem real-world and challenging:

"And one more thing here is: these are the deadlines for each job, and these are the times taken by each job. The amount of time taken for completion of the jobs is varying. It is not the same one unit of time — they are having different times!"

J3 1 hour 2 6 Needs 1 hour; must finish by 2:00

§12. The Solving Approach: State Space Tree

We solve this problem by systematically generating a State Space Tree. Let S be the set of jobs that are included in our current solution candidate:

  • Each node in the tree represents an active decision state specifying which jobs have been selected into S.
  • Branching creates child nodes by attempting to add further jobs into the schedule.
  • For every single node generated, we compute two specific mathematical values: Cost and Upper Bound.

§13. Defining the Two Node Values: Cost and Upper Bound

Here are the exact definitions of Upper Bound and Cost as explained in the lecture:

1. Upper Bound (u) All Excluded Jobs
"Upper bound for each node will be sum of all the penalties except those which are included in the solution. If S is the set of jobs that are included in a solution, then the upper bound is sum of the penalties of all those jobs which are not in that set."
Upper Bound = ∑j ∉ S (Penalty of Job j)

It represents the worst-case complete penalty if we stop adding any more jobs and only finish the jobs currently in set S.

2. Cost (&hat;c) Skipped Jobs Till k
"And the cost is sum of all the penalties till the job that you have considered. Cost is sum of all the penalties till the last job that we have considered — up to the k-th job that we have taken."
Cost = ∑j ≤ k, j ∉ S (Penalty of Job j)

It represents the penalties already locked in by all jobs we deliberately skipped up to the current job index k.

§14. Global Tracker `UPPER` & The Node Killing Condition

📌 1. Global Variable `UPPER`

We maintain a single global variable called UPPER across the entire algorithm:

  • It is initialized at the root node to ∞ (infinity).
  • Whenever a newly generated node produces an Upper Bound < UPPER, we immediately update: UPPER ← Upper Bound.
  • This keeps track of the best (lowest) complete penalty found so far in the search space.

⚔️ 2. The Pruning / Killing Rule

"What is the cost now? If cost has exceeded the upper bound, kill this node! That upper bound shows that if we are getting some penalty, at most we may be getting UPPER, but this cost has already exceeded it. So kill this node — no need of finding upper bound at all!"
IF (Cost > UPPER) ⇒ KILL NODE IMMEDIATELY (PRUNE)

Why kill it immediately? Because even the penalties locked in so far from skipped jobs already exceed the best complete solution available. Any child nodes branched from this node will only skip more jobs or incur more penalties, so they can never produce a penalty lower than UPPER!

§16. The State Space Tree Traversal Strategy

We generate the State Space Tree node by node. For every node, we identify and compute:

1. Cost (&hat;c): Sum of penalties of all jobs skipped up to the currently considered job index k.
2. Upper Bound (u): Sum of penalties of all jobs excluded from solution set S.
3. Global UPPER: Initialized to ∞. Updated whenever Upper < UPPER. If Cost > UPPER, KILL NODE!

§19. Step 3: Expanding Live Node 2 ($S = \{J_1\}$) → Generating Nodes 6, 7, 8

Feasibility of Expanding Node 6 ($S=\{J_1, J_2\}$) CANNOT EXPAND

Let us see what happens if we complete $J_1$ and $J_2$ together:

• $J_1$: $t_1 = 1$, deadline $d_1 = 1$ → Scheduled $[0, 1]$ ✔
• $J_2$: $t_2 = 2$, deadline $d_2 = 3$ → Scheduled $[1, 3]$ ✔
• Total time taken = $1 + 2 = 3$ hours. Both finish on time!

Can we now add Job 3 ($J_3$) to this schedule?

• $J_3$ deadline is $d_3 = 2$, and requires $t_3 = 1$ hour.
• But by time 3, the clock has reached 3 hours! $J_2$ needs 2 full hours ($1 \to 3$).
• There is NO time left to finish $J_3$ before deadline 2!
✗ Based on processing time, $J_3$ cannot be done! Need not generate this child node.

Can we add Job 4 ($J_4$) to Node 6?

$J_4$ also needs 1 hour with deadline $d_4 = 2$. With clock at 3 hours, $J_4$ is also completely infeasible! Therefore, Node 6 cannot produce any more feasible children.
Feasibility of Node 9 ($S=\{J_2, J_3\}$) FEASIBLE WINNER

Let us check if jobs $J_2$ and $J_3$ can be scheduled together:

• $J_3$: $t_3 = 1$, deadline $d_3 = 2$ → Scheduled $[0, 1]$ (finishes at 1 $\le 2$) ✔
• $J_2$: $t_2 = 2$, deadline $d_2 = 3$ → Scheduled $[1, 3]$ (finishes at 3 $\le 3$) ✔
• Total time taken = $1 + 2 = 3$ hours. Both finish strictly within their deadlines!

Can we append Job 4 ($J_4$) to Node 9?

• $J_4$ requires $t_4 = 1$ hour and has deadline $d_4 = 2$.
• We already used hour $[0, 1]$ for $J_3$. By time $t=1$, $J_2$ takes the machine until $t=3$.
• No free slot exists before deadline 2. Adding $J_4$ is infeasible.
✔ Thus, $S=\{J_2, J_3\}$ is a maximal, complete feasible schedule!
