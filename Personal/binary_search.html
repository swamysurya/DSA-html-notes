What is Binary Search?

**Binary Search** is an extremely efficient search algorithm that finds the position of a target value within a **sorted array**. It works by repeatedly dividing in half the portion of the list that could contain the target item.

🔑 Prerequisite & Search Range Contract

Binary Search requires the array to be **sorted** in ascending or descending order. It maintains boundary variables:

  • low: Points to the start of the valid search interval.
  • high: Points to the end of the valid search interval.
  • Midpoint Comparison: We evaluate `mid = low + (high - low) / 2`. If `key == arr[mid]`, target found. If `key > arr[mid]`, discard the left half (`low = mid + 1`). If `key < arr[mid]`, discard the right half (`high = mid - 1`).

Logarithmic Power

Because Binary Search cuts the active array size in half on every step, its search space contracts exponentially:
N → N/2 → N/4 → ... → 1 Searching a database of **1,000,000** elements takes at most **20 comparisons**.

Step-by-Step Bounds Trace

Page 2

Let us trace searching for target **25** in the sorted list: `[5, 8, 12, 15, 20, 25, 30, 35]`.

Step 1: Initial State (low=0, high=7)

• Midpoint: `mid = (0 + 7) / 2 = 3` (val = 15).
• Comparison: `25 > 15`. Discard left half; search range becomes `[4, 7]`.

Step 2: Second Interval (low=4, high=7)

• Midpoint: `mid = (4 + 7) / 2 = 5` (val = 25).
• Comparison: `25 == 25`. Target located! Search completes.

Binary Search Complexity Analysis

Page 3

Asymptotic Complexity Metrics

Case Scenario Time Complexity
Best Case The first computed midpoint `arr[mid]` matches target key directly. O(1)
Average Case Target is located after logarithmic shrinkage steps. O(log N)
Worst Case Target element is at one of the interval extremes, or absent. O(log N)

📝 Space Complexity:

  • Iterative Binary Search: Modifies pointers `low`/`high` in a loop, requiring O(1) constant space.
  • Recursive Binary Search: Allocates function stack frames for deep calls, consuming O(log N) stack space.
