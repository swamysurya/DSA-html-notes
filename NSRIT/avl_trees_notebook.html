1. What is an AVL Tree?

The AVL tree was introduced in the year 1962 by its inventors, Adelson-Velsky and Landis (which is where the name "AVL" comes from).

An AVL tree is a height-balanced binary search tree. This means that while it follows all the rules of a normal Binary Search Tree (BST) — where smaller numbers go to the left and larger numbers go to the right — it has one extra superpower: it keeps itself balanced.

The Balance Factor

To know if the tree is balanced, every node in an AVL tree calculates a "Balance Factor".

Formula: Balance Factor = [Height of Left Sub-tree] - [Height of Right Sub-tree]

For an AVL tree to be considered balanced, the balance factor for all nodes must be either 0, 1, or -1.

✍️ Note: Please don't count the number of nodes! Just count the height (the longest path of edges from the node down to the furthest leaf).
Balanced BST (AVL Tree)
All balance factors are 0, 1, or -1
Unbalanced BST (Non-AVL)
Root node has BF = -2 (Rule Broken!)
💡 Making the Connection: So, what happens if we add a new number to our tree, and suddenly a node gets a balance factor of 2 or -2? The tree is no longer an AVL tree! To fix this rule-breaking, we have to adjust the tree using a technique called "Rotation." Let's learn about that next.

2. AVL Tree Rotations

Rotations are the process of moving nodes either from left to right, or right to left, to make the tree balanced again. Rotations are used to convert a larger tree height into a smaller tree height.

There are four rotations, and they are classified into two types:

  • Single Rotation: Left Rotation and Right Rotation
  • Double Rotation: Left-Right Rotation and Right-Left Rotation

3. AVL Tree Operations

There are two main operations in an AVL tree: Insertion and Deletion.

Insertion

In an AVL tree, the insertion operation is performed by adding an element in a specific location. Here are the steps:

  1. Step-1: Insert the new element into the tree using standard Binary Search Tree (BST) logic.
  2. Step-2: After insertion, check the balance factor of every node.
  3. Step-3: If the balance factor of every node is 0, 1, or -1, then go for the next operation.
  4. Step-4: If the balance factor of any node is other than 0, 1, or -1, then the tree is said to be imbalanced. In this case, we perform suitable rotations to make it balanced and then go for the next operation.

Example: Construct an AVL Tree by inserting numbers 15, 20, 24, 10, 13.

Step-1: Insert 15

The tree is empty, so we create a new root node for 15. The balance factor is 0.

Step-2: Insert 20
Step 2.1: BST Insertion Search Path

Compare 20 > 15. We go right and insert 20 as the right child of 15.

Step 2.2: Balance Factor Calculation

Trace up: BF(20)=0, BF(15)=-1. All nodes are balanced, no rotation needed.

Step-3: Insert 24
Step 3.1: BST Insertion

Compare 24 > 15 (go right) & 24 > 20 (go right). Insert 24.

Step 3.2: Balance Check

Trace up: BF(24)=0, BF(20)=-1, BF(15)=-2 (Imbalance!). Pivot is 15.

Step 3.3: Left Rotation

Right-Right path imbalance. Rotate left at 15. Root becomes 20.

Step-4: Insert 10
Step 4.1: BST Insertion Search Path

Compare 10 < 20 (go left) & 10 < 15 (go left). Insert 10 as left child of 15.

Step 4.2: Balance Factor Calculation

Trace up: BF(10)=0, BF(15)=1, BF(24)=0, BF(20)=1. Tree is balanced.

Step-5: Insert 13
Step 5.1: BST Insert

Compare 13: Left of 20, Left of 15, Right of 10. Insert 13.

Step 5.2: Balance Check

BF(13)=0, BF(10)=-1, BF(15)=2 (Imbalance!). Pivot is 15.

Step 5.3: LR Phase 1

Left Rotate at child 10. 13 becomes 15's left child.

Step 5.4: LR Phase 2

Right Rotate at pivot 15. Subtree is now balanced.

4. Deletion Operation in AVL Tree

The delete operation in an AVL tree starts just like a standard Binary Search Tree (BST) deletion. However, removing a node changes the heights of the subtrees. We must trace back up the path to the root and check the balance of every node. If a node's balance factor becomes +2 or -2, we perform rotations to restore balance.

⚖️ AVL Deletion: The Balance Scale Analogy

Think of an AVL tree node as a balance scale. The left subtree sits on the left pan, and the right subtree sits on the right pan.

  • Deleting a node is like removing a weight from one of the pans.
  • If you remove a weight from the Right Pan, the scale tilts heavily to the left. The left child becomes too heavy (BF = +2). We call this an R-Rotation case (Right side lost weight).
  • If you remove a weight from the Left Pan, the scale tilts heavily to the right. The right child becomes too heavy (BF = -2). We call this an L-Rotation case (Left side lost weight).

To re-balance the scale, we look at the heavy child. If the child is leaning in the same direction, we do a quick Single Rotation. If the child is leaning in the opposite direction, it's a zigzag imbalance, so we perform a Double Rotation to straighten it out.

A. R-Rotations (Left-Heavy Imbalance, BF = +2)

These occur when we delete a node from the right side of a node A, leaving its left side too heavy. Let B be A's left child.

1. R0 Rotation (B has BF 0)

B's subtrees are perfectly balanced. We perform a single Right Rotation at A to shift the weight. (Height of the subtree remains unchanged).

Before R0 Rotation (BF of A is +2)
After R0 Rotation (Balanced)

2. R1 Rotation (B has BF +1)

B is left-heavy (leaning in the same direction). We perform a single Right Rotation at A to re-balance. (Height of the subtree decreases by 1).

After R1 Rotation (Balanced)

3. R-1 Rotation (B has BF -1)

B is right-heavy (leaning in the opposite direction). This is a zigzag imbalance. We perform a double Left-Right (LR) Rotation (Rotate B left, then rotate A right).

1. L0 Rotation (B has BF 0)

B's subtrees are perfectly balanced. We perform a single Left Rotation at A to shift the weight. (Height of the subtree remains unchanged).

Step 1: Delete 24 (Triggers R0 Right Rotation)

Locate 24 (leaf node) and remove it. Heights adjust.

1.2: Balance Check at Root 20

Root 20's left height is 2, right is 0. BF = 2 - 0 = +2 (Imbalanced!). Left child 13 has BF 0.

1.3: Single Right Rotation at 20

Rotate right at 20. Node 13 becomes the new root of the tree.

Step 2: Delete 10 (Triggers L1 Double Right-Left Rotation)

2.1: BST Deletion of 10

Locate and remove leaf 10. Node 13 has left child null.

2.2: Balance Check at 13

BF of 13 becomes 0 - 2 = -2. Right child 20 has BF +1 (opposite sign!).

2.3: Right Rotate at 20

Right rotate right child 20. 15 rises up as 13's right child.

2.4: Left Rotate at 13

Left rotate pivot 13. Node 15 becomes the new root of the tree.

5. Complexity Analysis of AVL Tree

Because an AVL tree guarantees that its height is kept logarithmic in relation to the number of nodes, it completely avoids the worst-case degradation of standard Binary Search Trees.

Operation Best Case Average Case Worst Case
Search O(1) (Root matches) O(log n) O(log n)
Insertion O(log n) O(log n) O(log n)
Deletion O(log n) O(log n) O(log n)
Space Complexity O(n) O(n) O(n)

Key Takeaways:

  • Standard Binary Search Trees can decay to O(n) search time (becoming a degenerate linked list) if values are inserted sequentially. AVL trees prevent this completely.
  • The space complexity is O(n) to store node values, height variables, and child pointers.
  • An AVL tree insertion takes at most one rotation operation to restore balance. Deletion may require up to O(log n) rotations as the balance updates propagate up the path to the root.
