What is std::unordered_set?

In C++, std::unordered_set is an associative container that stores unique elements in no particular order. Unlike std::set (which uses a self-balancing Red-Black Tree to maintain sorted order), the unordered set is implemented using a Hash Table under the hood.

🔑 Under-the-Hood Data Structure: Buckets & Chains

The hash table is essentially an array of slots called Buckets. When we insert an element, the container performs the following operations:

  1. Hash Computation: It applies a hash function (like std::hash<T>) to the element's key to get an integer value.
  2. Modulo Arithmetic: It maps this hash value to a specific bucket index: index = hash(key) % bucket_count.
  3. Chaining for Collision Resolution: If multiple elements map to the same bucket index (called a collision), they are stored in a singly-linked list (chain) associated with that bucket.

Concepts of Load Factor & Rehashing

💡 Load Factor: The ratio of the number of elements in the container to the number of buckets:

Load Factor (α) = N / B

Where N is the number of active elements and B is the bucket count. If α grows too large (typically exceeding 1.0), searching degrades to linear scanning. To prevent this, the set triggers Rehashing, which allocates more buckets and redistributes all keys.

Step-by-Step Chaining Walkthrough

Page 2

Let us walk through the process of inserting a sequence of numbers into an empty std::unordered_set with 5 buckets. We assume our hash function is the identity: hash(x) = x. Therefore, Bucket Index = x % 5.

Step 1: Initial Empty Hash Table

We start with a clean table of 5 buckets. All buckets contain null pointers (represent NIL pointers).

Step 2: Insert 12

• hash(12) = 12. Bucket Index = 12 % 5 = 2.
• Since bucket 2 is empty, we create a new node and insert it at index 2.

Step 3: Insert 7 (Collision!)

• hash(7) = 7. Bucket Index = 7 % 5 = 2.
• Bucket 2 already contains 12! We resolve this collision by inserting 7 at the head of the chain.

Step 4: Insert 22 (Collision!)

• hash(22) = 22. Bucket Index = 22 % 5 = 2.
• Bucket 2 has another collision. We insert 22 at the head of the chain: 22 → 7 → 12.

Step 5: Insert 15

• hash(15) = 15. Bucket Index = 15 % 5 = 0.
• Index 0 is empty, so we insert 15 directly.

STL Methods & Complexity Analysis

Page 3

Primary std::unordered_set Operations

Method Description Average Time Worst-Case Time
insert(val) Inserts the value into the set if it doesn't already exist. O(1) O(N)*
erase(key) Removes the element matching the key. O(1) O(N)
find(key) Returns an iterator to the element if found, or end() if not. O(1) O(N)
count(key) Returns 1 if the element is present, else 0 (since keys are unique). O(1) O(N)
bucket_count() Returns the total number of buckets in the container. O(1) O(1)
load_factor() Returns the average size of buckets: size() / bucket_count(). O(1) O(1)
rehash(n) Sets the bucket count to at least n and rebuilds the hash table. O(N) O(N2)

📝 Rationale behind complexities:

  • Average Case O(1): In a well-designed hash table, keys are distributed uniformly across buckets. The average length of each linked list is limited to the load factor threshold (≤ 1.0). Finding an element requires calculating the hash index (O(1)) and scanning a list of length ≤ 1 (O(1)).
  • Worst Case O(N): Occurs when the hash function is poor and maps all elements to the exact same bucket. The container degrades to a single linked list, causing insertion, deletion, and searches to take linear scan time, O(N).
  • * Rehashing overhead: When insertion triggers rehashing, the time complexity for that specific insertion becomes O(N) because every element must be hashed again and moved to a new bucket. Amortized over many inserts, it is still O(1).
