Greedy Method - General Concept

Page 1

1. What is the Greedy Method?

The Greedy Method is a practical strategy for solving Best Choice Problems (Optimization Problems). Instead of analyzing every possible combination of decisions, it builds a solution step-by-step by always making the most attractive choice at that exact moment. We call this a heuristic shortcut because it is fast and easy to use.

💡 Everyday Example: Imagine walking through a grocery store looking for snacks. A greedy shopper who wants the cheapest snacks will walk down the aisle and simply grab the lowest-priced item they see first, without checking if there are better value deals or coupons further down the aisle.

2. The Core Greedy Concept

At each stage, the algorithm makes the locally optimal choice—meaning the best immediate decision right now based only on what is directly in front of you. It hopes that stacking these choices will lead to a globally optimal solution (the absolute best final outcome overall).

Once a choice is made, it is permanent. The algorithm never goes back to change its mind (no backtracking). Because it only looks at immediate gains, it does not guarantee finding the best overall solution for every problem.

🪙 How Greedy Coin Selection Works:

The greedy selection rule is: "Always pick the largest coin denomination that is less than or equal to the remaining change amount."

✨ Scenario 1: Where Greedy Works (Optimal)

Goal: Make change for 36¢ using coins: [25¢, 10¢, 5¢, 1¢].

  • Step 1: Remaining is 36¢. Pick largest ≤ 36¢: 25¢. (Leftover: 11¢)
  • Step 2: Remaining is 11¢. Pick largest ≤ 11¢: 10¢. (Leftover: 1¢)
  • Step 3: Remaining is 1¢. Pick largest ≤ 1¢: 1¢. (Leftover: 0¢)

Greedy Result: 3 coins (25¢ + 10¢ + 1¢). This is the best overall solution.

⚠️ Scenario 2: Where Greedy Fails (Suboptimal)

Goal: Make change for 40¢ using coins: [25¢, 20¢, 10¢, 5¢, 1¢].

  • Step 1: Remaining is 40¢. Pick largest ≤ 40¢: 25¢. (Leftover: 15¢)
  • Step 2: Remaining is 15¢. Pick largest ≤ 15¢: 10¢. (Leftover: 5¢)
  • Step 3: Remaining is 5¢. Pick largest ≤ 5¢: 5¢. (Leftover: 0¢)

Greedy Result: 3 coins (25¢ + 10¢ + 5¢).

Optimal Solution: 2 coins (20¢ + 20¢).

Why it failed: Greedy picked the large 25¢ coin first without checking if skipping it for the smaller 20¢ coin would yield a better final outcome.

3. Feasible vs. Optimal Solutions

It is important to understand the difference between a solution that is simply allowed versus a solution that is the absolute best:

  • Feasible Solution ("A Valid Solution"): Any plan that obeys all the rules and fits within the limits (Constraints) of the problem. It is a valid answer, but not necessarily the best one.
  • Optimal Solution ("The Best Solution"): The single feasible solution that achieves the best possible score (the maximum profit or the minimum cost).
🎒 Backpack Example: If your backpack has a weight limit of 10 kg:
  • Packing books weighing 7 kg is a feasible solution because it is under the weight limit (rules are obeyed).
  • Packing books weighing exactly 10 kg that are the most valuable books is the optimal solution because it gives you the highest value without exceeding the limit.

4. The 5 Main Components

Every greedy algorithm uses these five simple building blocks to pick elements and construct its solution:

1. Candidate Set ("Option Pool"):

The starting collection of choices or inputs from which we construct our solution.

🪙 Coin Change: All available coin denominations we are allowed to use (e.g. [25¢, 10¢, 5¢, 1¢]).
2. Selection Function ("Picking Rule"):

The rule used to pick the single best item at the current step.

🪙 Coin Change: "Always select the largest coin value that fits within the remaining change amount."
3. Feasibility Function ("Rule Checker"):

Checks if the chosen candidate obeys all rules (e.g. does not exceed target limits).

🪙 Coin Change: If we need 1¢ more to reach 36¢, picking a 10¢ coin is infeasible (violates the target limit) and gets rejected.
4. Objective Function ("Score Calculator"):

Calculates the score or value of the solution subset at any point.

🪙 Coin Change: Summing up the values of selected coins (e.g., 25¢ + 10¢ = 35¢) and keeping track of the total number of coins used.
5. Solution Function ("Finish Line Check"):

Determines when a full, valid final solution is formed so we can stop the loop.

🪙 Coin Change: Checking if the sum of our selected coins matches the target change amount (e.g., 36¢). If yes, we terminate.

Greedy Selection & Feasibility Filter

Here is the visual flow of elements moving from the raw Option Pool, through the Selection and Feasibility filters, and into the final Solution Set container.

5. General Greedy Algorithm Structure

Algorithm Greedy(a, n): 
Algorithm Greedy(a, n)
{
    solution = empty; // Start with an empty solution set

    for i = 1 to n do
    {
        x = selection(a); // Pick the best candidate element 'x' from array 'a'

        if Feasible(solution, x) then // Check if adding 'x' is valid
        {
            solution = solution + x; // Include 'x' into the solution set
        }
    }
    return solution;
}
How the Code Works:

The program loops through all n potential candidates in your array a. In each iteration:

  • It calls selection() to pick the single best item x based on the greedy rule.
  • It passes x to Feasible() to check if including it violates any rules.
  • If Feasible() returns true, x is added to the solution set.

Fractional Knapsack Problem

Page 2

1. Problem Overview

The Fractional Knapsack Problem is a classic optimization problem. You are given a bag (knapsack) that can hold a maximum weight capacity of M. You have a list of items, where each item has a specific weight and profit value.

Key Terms Explained:
• Knapsack Capacity (M): The maximum weight limit the bag can safely hold.
• Fractional Selection: Unlike the 0/1 knapsack where you must either take an item fully or leave it, here you are allowed to cut items and take a fraction of them (e.g. half a block of cheese) to maximize profit.
• Goal: Fill the bag to get the highest total profit without breaking the weight limit.

2. Step-by-Step Greedy Algorithm

  1. Calculate Value Ratio (Profit / Weight): For every item, calculate how much profit it gives you per 1 kg. This ratio tells us how "valuable" the item is.
  2. Sort Items: Sort all items in descending order based on their value ratio (highest ratio first). This is the greedy rule!
  3. Pack Fully: Go down the sorted list. Take items and pack them fully into the bag as long as they fit. Reduce the remaining bag capacity accordingly.
  4. Pack Fractionally: If the next item on the list does not fit fully, cut it! Take only the fraction of that item needed to fill the remaining capacity of the bag exactly to zero.
  5. Compute Max Profit: Calculate the sum of profits of all full and fractional items loaded.

Job Sequencing with Deadlines

Page 3

1. Problem Overview

In the Job Sequencing with Deadlines problem, you are given a set of jobs where each job takes exactly 1 unit of time to complete. Each job comes with a deadline and a profit reward.

Key Terms Explained:
• Job: A task to be done. We can only work on one job at a time.
• Deadline: The time limit. If a job has a deadline of 3, it must finish by time 3 (so it can be scheduled in slot 1, 2, or 3). The smallest deadline is 1.
• Profit: The cash or score reward you get, but only if you complete the job before its deadline.
• Goal: Select and schedule a combination of jobs that fits the deadlines and earns the maximum possible profit.

2. General Greedy Algorithm Steps

The greedy strategy works by prioritizing the most profitable jobs first and placing them as late as possible before their deadlines. Here is the step-by-step procedure:

  1. Find Maximum Deadline: Find the highest deadline among all jobs. This tells us the total number of time slots available (e.g. if max deadline is 4, we have 4 slots: 1, 2, 3, and 4).
  2. Sort by Profit: Sort all jobs in descending order (highest profit first). This is the greedy choice rule!
  3. Place in Latest Slot: Pick the sorted jobs one by one. Try to schedule each job in its latest possible slot before its deadline (e.g., if deadline is 3, try Slot 3. If taken, try Slot 2, then Slot 1). If all slots before its deadline are full, skip the job.
  4. Calculate Profit: Sum the profits of all successfully scheduled jobs.

3. Example 1 Step-by-Step Scheduling

Jobs J₁ J₂ J₃ J₄ J₅
Deadline 2 2 1 3 4
Profit 20 60 40 100 80
Step 0: Initialize & Sort

Sorted Order: J₄ (100), J₅ (80), J₂ (60), J₃ (40), J₁ (20).

Max Deadline: 4. We initialize 4 empty slots.

Step 1: Process J₄ (Profit: 100, Deadline: 3)

We try to place J₄. Its deadline is 3. The latest possible slot before time 3 is Slot 3 (time 2 to 3). Since it is free, we schedule J₄ there.

Current Profit: 100

Step 2: Process J₅ (Profit: 80, Deadline: 4)

We try to place J₅. Its deadline is 4. The latest possible slot before time 4 is Slot 4 (time 3 to 4). Since Slot 4 is free, we schedule J₅ there.

Current Profit: 100 (J₄) + 80 (J₅) = 180

Step 3: Process J₂ (Profit: 60, Deadline: 2)

We try to place J₂. Its deadline is 2. The latest possible slot before time 2 is Slot 2 (time 1 to 2). Since Slot 2 is free, we schedule J₂ there.

Current Profit: 180 + 60 (J₂) = 240

Step 4: Process J₃ (Profit: 40, Deadline: 1)

We try to place J₃. Its deadline is 1. The latest slot before time 1 is Slot 1. It is free, so we schedule J₃.

Current Profit: 240 + 40 (J₃) = 280

Step 5: Process J₁ (Profit: 20, Deadline: 2)

We evaluate J₁. Its deadline is 2. We search backwards from Slot 2 to Slot 1, but both slots are already occupied (by J₂ and J₃). Thus, J₁ is skipped.

Final Output: Scheduled Jobs = {J₃, J₂, J₄, J₅}
🏆 Optimal Profit: 280

Minimum Cost Spanning Tree

Page 4

1. What is a Spanning Tree?

A spanning tree is a subset of an undirected, connected graph that connects all the vertices together with the minimum possible number of edges. It has three key properties:

  • Vertex Coverage: It must include every vertex (n) of the original graph.
  • Edge Count: It must contain exactly n - 1 edges (where n is the number of vertices).
  • Acyclic: It must not contain any cycles (loops).
Example: A square graph (left) and its 4 valid spanning trees (right)

2. What is a Minimum Cost Spanning Tree?

For a weighted graph, we can construct many different spanning trees. A Minimum Cost Spanning Tree (MCST) is the spanning tree where the sum of the edge weights is the absolute minimum among all possible spanning trees.

Example: Let us take an 8-vertex graph as illustrated in the visual charts, with the following edge weights:
• Top Row: A-B = 3, B-C = 1, C-D = 7
• Vertical Connections: A-E = 4, B-F = 2, C-G = 6, D-H = 2
• Bottom Row: E-F = 5, F-G = 5, G-H = 9

Algorithms for MCST:

There are two classic greedy algorithms used to find the Minimum Cost Spanning Tree of a connected, weighted graph:

  • Prim's Algorithm: Starts from a single vertex and grows the tree by adding the cheapest node connected to the current tree.
  • Kruskal's Algorithm: Sorts all edges by weight and adds the cheapest edge that does not form a cycle, regardless of connectivity.

3. Prim's Algorithm

Prim's algorithm is a greedy algorithm that grows the spanning tree one vertex at a time, starting from any arbitrary root vertex.

Prim's Steps:
• Step 1: Start with any vertex (e.g. Node A) and add it to the visited set.
• Step 2: Find the minimum-weight edge connecting any visited vertex to any unvisited vertex.
• Step 3: Add this edge and vertex to the tree, verifying it doesn't create a cycle (since the target is unvisited, it will never form a cycle!).
• Step 4: Repeat until all vertices are visited.

4. Kruskal's Algorithm

Kruskal's algorithm sorts all edges by weight and processes them greedily, adding an edge only if it does not form a cycle with already selected edges.

Kruskal's Steps:
• Step 1: List all edges and sort them in non-decreasing (increasing) order of weight.
• Step 2: Pick the cheapest edge. Check if adding it forms a cycle in the tree built so far (using Union-Find).
• Step 3: If it forms a cycle, discard it. If not, accept it and include it in the MCST.
• Step 4: Repeat until we have successfully accepted exactly n - 1 edges.

Single Source Shortest Paths

Page 5

1. Single Source Shortest Path (SSSP)

Given a directed, weighted graph G = (V, E) and a designated Source Vertex, our goal is to find the shortest path (minimum total edge weight) from the source vertex to all other vertices in the graph.

2. Dijkstra's Algorithm

Dijkstra's algorithm is a greedy algorithm quite similar to Prim's. It maintains a set of visited vertices and repeatedly relaxes adjacent edge weights to find the shortest paths.

Dijkstra's Steps:
• Step 1: Initialize distance to source node as 0, and all other nodes as ∞. Set the visited set to empty.
• Step 2: From the unvisited set, select the vertex u with the minimum tentative distance.
• Step 3: Add u to the visited set.
• Step 4: Update (relax) the distance values of all unvisited neighbors of u. If dist[u] + weight(u, v) < dist[v], update dist[v].
• Step 5: Repeat steps 2-4 until all nodes are visited.
💡 Understanding Edge Relaxation (3-Node Example)

Relaxation is the act of checking if a shorter path to a target node can be found by traveling through an intermediate node instead of the currently known path.

1. Initial State:
  • Path to intermediate node B (represents node 'u') has cost: d(u) = d(B) = 5
  • Current path to target node C (represents node 'v') has cost: d(v) = d(C) = 12
  • Edge connecting u → v (B → C) has weight: w(u, v) = 4
2. Relaxation Formula:
if (d(u) + w(u, v) < d(v)) {
  d(v) = d(u) + w(u, v);
}
3. Calculation & Update:

Is d(u) + w(u, v) < d(v)? (Is 5 + 4 < 12? Yes, 9 < 12).

Result: d(v) is relaxed and updated from 12 to 9!
