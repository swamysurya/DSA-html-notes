What is std::deque?

In C++, std::deque (stands for Double-Ended Queue) is a sequence container that allows fast insertion and deletion at both the beginning and the end.

🔑 Under-the-hood: Map of Chunk Pointers

Unlike vectors which use a single contiguous memory block, a deque uses a **central map of pointer blocks** pointing to several independent fixed-size contiguous memory blocks called **chunks**:

  • Chunk blocks: Fixed-size contiguous arrays (e.g., 512 bytes or 8 element slots).
  • Map Array: A central array containing pointers to these chunk arrays.
  • Two-way Grow bounds: Pushing at the back fills the right-side chunks. Pushing at the front fills the left-side chunks. If we run out of slots, we simply allocate a new chunk block and add its address in the central map.

Key Architecture Benefits

💡 Constant Time push/pop: Adding or removing at either end takes strictly **O(1)** time and never requires shifting other elements (unlike vector's front inserts).

💡 Index access O(1): To read `deque[i]`, the library computes which chunk stores the element in constant time: chunk = (i + offset) / chunk_size, keeping random access fast.

Conceptual Pointer Map Layout: Central Map pointers point to horizontal memory blocks.

Let us trace pushing values at the front and back of a deque using **chunk size = 3**.

Step 1: Empty State

Central map points to a single allocated chunk in the center. All elements are null.

Step 2: Push Back 10, Push Back 20

Items are filled in the center chunk slots.

Step 3: Push Front 30, Push Front 40 (Allocates left chunk!)

• Pushing 30 fills the first slot of the center chunk.
• Pushing 40 runs out of left space! The deque allocates a new chunk to the left of the map index, and writes 40 in it.

Deque Methods & Complexity Analysis

Page 3

Primary std::deque Operations

Method Description Average Time Worst-Case Time
push_back(val) / push_front(val) Adds element to the back or front boundaries. O(1) O(1)
pop_back() / pop_front() Removes element from back or front. O(1) O(1)
operator[idx] Returns element at index. Computes chunk offset. O(1) O(1)
insert() / erase() Insert/erase in middle. Shifts elements in closest direction. O(N) O(N)

📝 Deque vs. Vector:

  • No resizing copies: Because elements are added by allocating new chunks, deque insertion does not copy existing elements to new blocks (unlike vector).
  • Non-contiguous items: Elements are contiguous inside individual chunks, but chunks themselves are not contiguous. Thus, passing `&deque[0]` to an API requiring a raw C-pointer is invalid.
  • Double-ended optimization: Perfect choice for implementing stacks, queues, or sliding window problems.
