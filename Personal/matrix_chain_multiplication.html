📐 Step 1: When Can Two Matrices Be Multiplied?

Let us take two matrices, A and B:

  • Matrix A has dimensions 2 × 3 (2 rows, 3 columns).
  • Matrix B has dimensions 3 × 2 (3 rows, 2 columns).
🚨 The Golden Rule of Matrix Multiplication:

Two matrices can be multiplied if and only if the number of columns of the first matrix is equal to the number of rows of the second matrix:

Columns(A) == Rows(B)  ⇒  3 == 3  ✅ Compatible!
Visualizing (2 × 3) × (3 × 2) = (2 × 2) Dot Products Each element in C requires multiplying a row of 3 elements by a column of 3 elements.

Three Crucial Facts to Pick Up:

1. Compatibility Condition:

Inner dimensions must match: (p × q) × (q × r).

2. Resulting Dimension:

The extreme dimensions form the result: (p × r), i.e., 2 × 2.

3. Multiplications Required:

Total = p × q × r = 2 × 3 × 2 = 12 multiplications!

💡 Dimension Array Representation:

Since adjacent matrices share their inner dimension (columns of A₁ = rows of A₂), we avoid repeating numbers and compress the dimensions of all n matrices into a single array d of length n + 1.
For example, if d = [10, 20, 30] (3 numbers for 2 matrices), then matrix A₁ is d₀ × d₁ (10 × 20) and matrix A₂ is d₁ × d₂ (20 × 30).
In general, each Matrix Aᵢ sits between indices dᵢ₋₁ and dᵢ, so its size is always dᵢ₋₁ × dᵢ.

⛓️ Step 2: The 3-Matrix Chain Example (Why Order Changes Everything!)

Suppose we have 3 matrices to multiply: A₁ × A₂ × A₃ with dimensions:

Matrix A₁ 2 × 3 d₀=2, d₁=3

"Observe this carefully! For just 3 small matrices, Option 2 takes only 36 multiplications, while Option 1 takes 40! A difference of 4 multiplications. If we have 10, 20, or 100 matrices, the difference between a poor parenthesization and an optimal one is not 4—it is millions or billions of operations! Therefore, before multiplying, we must determine: How should the matrices be parenthesized to minimize the total scalar multiplications?"

2. Why Brute Force Fails & Deriving the Formula

Catalan Numbers Growth • How the Teacher Turns the 3-Matrix Math into the DP Formula

Page 2

📈 Why Can't We Just Try All Parenthesizations? (Catalan Numbers)

How many different ways can we parenthesize a chain of n matrices? For n = 3, there were only 2 ways. But for n = 4, there are 5 ways:

1. A₁ × (A₂ × (A₃ × A₄))
2. A₁ × ((A₂ × A₃) × A₄)
3. (A₁ × A₂) × (A₃ × A₄)
4. ((A₁ × A₂) × A₃) × A₄
5. (A₁ × (A₂ × A₃)) × A₄
📐 The Catalan Number Formula (Parenthesization Count) Combinatorics

How many ways can n matrices be parenthesized? Here is the exact, step-by-step formula derivation as written in the lecture:

Step 1: General n-th Catalan Number Formula The standard mathematical definition of Catalan numbers:
2nCn n + 1
Step 2: For n Matrices in MCM (Substitute n - 1) Since n matrices require placing (n - 1) operations, replace n with (n - 1):
2(n - 1)C(n - 1) n
✍️ Step 3: Example with n = 4 (As Solved on the Board) Result = 5
If n = 4: 2 × 3C3 4 = 6C3 4 = 1 6 × 5 × 4 3 × 2 × 1 4 = 5
✂️ How the cancellations happen:
  • In the numerator, ⁶C₃ = (6 × 5 × 4) / (3 × 2 × 1).
  • The 3 × 2 = 6 in the sub-denominator cancels directly with the 6 in the numerator (leaving 1).
  • The 4 in the numerator cancels directly with the outer denominator 4.
  • Only 5 remains! Thus, exactly 5 parenthesizations!
Similarly for n = 5 Matrices: Total = 14 Ways
If n = 5: 2 × 4C4 5 = 8C4 5 = 70 5 = 14 Parenthesizations
📊 Growth of Parenthesizations with Matrix Count (n): P(n) = Ω(4ⁿ / n3/2)
n (# Matrices) 2 3 4 5 6 10 20
Catalan P(n) 1 2 5 14 42 4,862 1,767,263,190 (~1.77×10⁹)
"For 10 matrices, you cannot test 4,862 combinations by hand! Brute force is exponential Ω(4ⁿ / n³/²). We must use Dynamic Programming to solve smaller overlapping subproblems once and build up to the global minimum!"

🚀 General Formula Mapping (Aᵢ .. Aⱼ) Any i to j

See how every concrete number from the 3-matrix example directly becomes a general variable:

Concrete Term (k = 1) ➔ General Variable
Start matrix A₁ ➔ Matrix Aᵢ
End matrix A₃ ➔ Matrix Aⱼ
Split cut location k = 1, 2 ➔ Cut index k (i ≤ k < j)
Cost of Left: C(1, k) ➔ C(i, k)
Cost of Right: C(k+1, 3) ➔ C(k+1, j)
Multiply cost: d₀ × dₖ × d₃ ➔ di-1 × dk × dj
The 3 Anatomy Pieces of the Dynamic Programming Formula
C(i, j) = mini ≤ k < j { C(i, k) + C(k+1, j) + di-1 · dk · dj }
1. C(i, k)

Cost of optimally parenthesizing the Left Subchain from matrix Aᵢ to Aₖ. Result has size di-1 × dk.

2. C(k+1, j)

Cost of optimally parenthesizing the Right Subchain from matrix Aₖ₊₁ to Aⱼ. Result has size dk × dj.

3. di-1 · dk · dj

Cost to multiply the two resulting matrices together! (Left rows di-1 × Common dimension dk × Right cols dj).

Base Case: C(i, i) = 0 (A chain of length 1 is already a single matrix, requiring 0 multiplications).

💡 The Teacher's Whiteboard Conclusion:

"Look at the board! When computing C[1, 4], branch k = 1 calls C[2, 4]. When C[2, 4] expands at k = 2, it requires C[3, 4].
But look right above it: the k = 2 branch of C[1, 4] ALSO requires C[3, 4]!
In naive recursion, this identical subproblem is solved independently multiple times. For 10 or 20 matrices, this redundancy explodes exponentially into billions of wasted recalculations! Therefore, we must NOT use top-down recursion — we must fill a table bottom-up in order of increasing difference (chain length)!"

📐 The Diagonal Strategy: Solve by Difference (Chain Length)

Instead of starting from the large problem C(1, 4), we start from the smallest difference between i and j: let difference s = j - i:

Diff s = 0 (Length 1)

Main Diagonal: j - i = 0

C(1,1), C(2,2), C(3,3), C(4,4) = 0 Single matrices take 0 multiplications.
Diff s = 1 (Length 2)

1st Superdiagonal: j - i = 1

C(1,2), C(2,3), C(3,4) Only 1 possible split point k.
Diff s = 2 (Length 3)

2nd Superdiagonal: j - i = 2

C(1,3), C(2,4) 2 possible values of k.
Diff s = 3 (Length 4)

Corner Cell: j - i = 3

C(1,4) ← FINAL GOAL! 3 possible values of k.
Diagonal Table Filling Sequence Always fill along diagonals: s=0 → s=1 → s=2 → s=3.
📋 We Need Two Separate Tables:
  • Cost Table (C or M Table): Stores the minimum number of scalar multiplications for subchain Aᵢ .. Aⱼ.
  • Split Table (K or S Table): Stores the value of k that gave the minimum cost for subchain Aᵢ .. Aⱼ. This table is later used to reconstruct the exact parentheses!

⏱️ Step 2: Time & Space Complexity Analysis

Time Complexity: O(n³)

1. How many entries are there in the upper triangular table?
    n(n + 1) / 2 ≈ O(n²) cells.
2. For each cell C(i, j), split point k loops from i to j - 1, which takes at most n iterations.
3. Multiplying O(n²) cells by O(n) choices per cell gives:

Total Time = O(n²) × O(n) = O(n³)
This is an upper bound. A tighter summation still yields Θ(n³).
Space Complexity: O(n²)

We maintain two n × n tables:

  • Cost matrix C[n × n]
  • Split matrix K[n × n]

Total Auxiliary Space = O(n²)

// Matrix Chain Multiplication using Dynamic Programming
// Dimensions array d of size (n + 1): Matrix A[i] has dimension d[i-1] x d[i]
#include <iostream>
#include <vector>
#include <climits>
using namespace std;

void printOptimalParens(int i, int j, const vector<vector<int>>& K) {
    if (i == j) {
        cout << "A" << i;
    } else {
        cout << "(";
        printOptimalParens(i, K[i][j], K);
        printOptimalParens(K[i][j] + 1, j, K);
        cout << ")";
    }
}

void matrixChainOrder(const vector<int>& d, int n) {
    vector<vector<int>> C(n + 1, vector<int>(n + 1, 0));
    vector<vector<int>> K(n + 1, vector<int>(n + 1, 0));

    // s is the chain length / difference (j - i)
    for (int s = 1; s < n; s++) {
        for (int i = 1; i <= n - s; i++) {
            int j = i + s;
            C[i][j] = INT_MAX;
            for (int k = i; k < j; k++) {
                int cost = C[i][k] + C[k + 1][j] + d[i - 1] * d[k] * d[j];
                if (cost < C[i][j]) {
                    C[i][j] = cost;
                    K[i][j] = k;
                }
            }
        }
    }

    cout << "Minimum Multiplications: " << C[1][n] << endl;
    cout << "Optimal Parenthesization: ";
    printOptimalParens(1, n, K);
    cout << endl;
}
