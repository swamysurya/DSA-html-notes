What is Merge Sort?

**Merge Sort** is an efficient, general-purpose, comparison-based sorting algorithm. It utilizes a **divide-and-conquer** strategy to divide the input array into two halves, calls itself recursively on the halves, and then merges the two sorted halves back together.

🔑 Divide, Conquer, & Merge

  • Divide: Calculate the middle index `mid = low + (high - low) / 2` and split the array into two halves recursively.
  • Conquer: Continue splitting until subarrays reach singleton sizes (length 1), which are sorted by default.
  • Merge: Combine adjacent sorted subarrays by stepping through both, copying smaller elements sequentially into a temp array.

Stable Merge Step

When merging `arr[L]` and `arr[R]`, if elements are equal, we choose the element from the left subarray first. This guarantees that duplicate items maintain their relative input orders, making Merge Sort **stable**.

Let us trace merge sorting the array: `[4, 2, 1, 3]`.

Step 1: Partition down to Singletons

• Split `[4, 2, 1, 3]` into left `[4, 2]` and right `[1, 3]`.
• Sub-splits reach singletons: `[4]`, `[2]`, `[1]`, `[3]`.

Step 2: Merge sorted halves recursively

• Merge `[4]` and `[2]` into sorted `[2, 4]`. Merge `[1]` and `[3]` into `[1, 3]`.
• Merge `[2, 4]` and `[1, 3]` into the final sorted array `[1, 2, 3, 4]`.

Merge Sort Complexity Analysis

Page 3

Asymptotic Runtime Bounds

Case Scenario Time Complexity
Best Case Array is already sorted. Split structure remains identical, still taking O(N log N) merge operations. O(N log N)
Average Case Elements are randomly distributed. Consistently partitions and merges halves. O(N log N)
Worst Case Elements are configured to trigger the maximum number of comparisons in merge. O(N log N)

📝 Space Complexity:

Because merging requires allocating a separate temporary workspace of size N to copy values back and forth, the space complexity is **not in-place**:
Space Complexity = O(N) (Auxiliary space)
