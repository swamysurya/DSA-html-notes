Dijkstra's Algorithm Concepts

Page 1

1. Introduction

Dijkstra's algorithm is a fundamental graph algorithm used to solve the **Single Source Shortest Path (SSSP) Problem**.

Given a weighted graph and a starting vertex (source), our goal is to find the shortest path from the source to all other vertices in the graph.

SSSP Example:
If we choose node 1 as our source:
  • Shortest path to Node 2: 1 → 2 (or via other nodes)
  • Shortest path to Node 3: 1 → 3 (direct or indirect)
  • Shortest path to Node 4: 1 → 2 → 4 (etc.)

2. Dijkstra & The Greedy Method

Finding the shortest path is a minimization problem, which is a type of **Optimization Problem**.

Optimization problems can often be solved efficiently using a **Greedy Method**. The greedy method solves a problem in stages:

  • Takes one step at a time, selecting the best local choice.
  • Considers one input element at a time.
  • Follows a predefined sequence of steps.
  • Aims to arrive at a global optimal solution.

3. Graph Support

Dijkstra's algorithm is versatile and runs successfully on:

  • Directed Graphs
  • Non-Directed (Undirected) Graphs

However, the algorithm has a critical drawback when the graph contains negative-weight edges.

4. Relaxation Concept

The core mathematical operation in Dijkstra's algorithm is **Relaxation**.

Suppose we have an edge from vertex U to vertex V with a weight/cost cost(U, V):

Relaxation Formula: If distance(U) + cost(U, V) < distance(V),
then modify distance(V) = distance(U) + cost(U, V).

Initially, all nodes have their distances set to infinity (∞), except the source which is 0. As we discover paths, we "relax" the edges to lower the estimated distances.

Visualizing relaxation: path distance to node 3 updates from ∞ to 6 through node 2.

Let us perform a step-by-step dry run on a weighted graph with 6 vertices starting from **Source = 1**.

Initial Setup & Step 1

Direct distances from Source 1: d(2)=2, d(3)=4. All others set to ∞.
Smallest unvisited distance is 2 (Node 2). Select it.
Relax from 2:
* Node 3: d(2) + cost(2,3) = 2 + 1 = 3 < 4 → Update d(3) = 3.
* Node 5: d(2) + cost(2,5) = 2 + 7 = 9 < ∞ → Update d(5) = 9.

Step 2: Select Node 3

Current distances: d(3)=3, d(5)=9. Smallest is 3 (Node 3). Select it.
Relax from 3:
* Node 5: d(3) + cost(3,5) = 3 + 3 = 6 < 9 → Update d(5) = 6.

Step 3: Select Node 5

Remaining distances: d(5)=6, d(4)=9. Smallest is 6 (Node 5). Select it.
Relax from 5:
* Node 4: d(5) + cost(5,4) = 6 + 2 = 8 < 9 → Update d(4) = 8.
* Node 6: d(5) + cost(5,6) = 6 + 5 = 11 < ∞ → Update d(6) = 11.

Step 4: Select Node 4

Remaining: d(4)=8, d(6)=11. Smallest is 8 (Node 4). Select it.
Relax from 4:
* Node 6: d(4) + cost(4,6) = 8 + 1 = 9 < 11 → Update d(6) = 9.

Node 4 (0) 50 45 (10) 25 ∞

Node 2 (0) (45) 45 (10) (25) ∞
Node 3 (0) (45) (45) (10) (25) ∞

* Step 1: The smallest unselected distance is 10. We select Node 4. Relax edge `4 → 5` (weight 15) → `d(5) = 10 + 15 = 25 < ∞`.

* Step 2: The smallest unselected distance is 25. We select Node 5. Relax edges:
• Node 2: `d(5) + cost(5,2) = 25 + 20 = 45 < 50` → update `d(2) = 45`.
• Node 3: `d(5) + cost(5,3) = 25 + 20 = 45` → no improvement (equal to 45).

* Step 3 & 4: We select Node 2 and Node 3. Relaxation checks yield no improvements. Node 6 has no paths leading to it, so its distance remains ∞.

Drawbacks & Performance

Drawback: Negative Edges

Dijkstra's algorithm assumes that edge weights are positive. If a graph contains negative weights, Dijkstra's algorithm may or may not work correctly.

The greedy assumption states that once a vertex is chosen and its distance finalized, we don't need to re-evaluate it. Negative weights break this because a much shorter path (due to a heavy negative decrease) can be discovered later.

⚠️ Dijkstra Breakdown Example:
1. Direct edge `Source → A` cost is 3. Select A = 3 and lock it in.
2. Direct edge `Source → B` cost is 5. Select B.
3. From B to C cost is 2, updating C to 7. Select C.
4. From C to A there is a negative edge of weight -10.
Path `Source → B → C → A` has cost `5 + 2 - 10 = -3`. This is shorter than 3, but Dijkstra has already finalized A's cost as 3 and will not re-check it, outputting an incorrect path cost!
Dijkstra fails here: path to A can be improved to -3 after A is visited.

Dijkstra Time Complexity

Dijkstra's worst-case time complexity is:

Θ(n²) or Θ(V²)

In a complete graph, every vertex is connected to all other vertices. Finding the minimum distance vertex and relaxing all of its outgoing edges takes $\Theta(n^2)$ time in the standard array-based implementation.

💡 SSSP Alternative: To resolve shortest paths in graphs containing negative edges, we use the Bellman-Ford Algorithm (based on Dynamic Programming), which re-evaluates edges multiple times.

Important Exam Questions

Q: Which problem does Dijkstra's algorithm solve? A: The Single Source Shortest Path (SSSP) problem.
Q: What algorithm design paradigm is used? A: The Greedy Method.
Q: Can it handle negative edges? A: No, it may fail because it relies on local greedy choices that cannot be updated.
Q: What is the worst-case time complexity? A: Θ(n²) using a standard array structure. Can be optimized to O(E log V) using a binary heap.
