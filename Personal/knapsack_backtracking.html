1. 0/1 Knapsack Problem using Backtracking

Formal problem definition, example dataset table, decision-tuple model, and bounding functions

Exam Standard • Unit 7
📝 Professor's Note: "In Dynamic Programming, we compute tabular subproblems systematically. But in Backtracking, we explore the solution space as a Depth-First State-Space Tree. At each stage, we either include ($x_i = 1$) or exclude ($x_i = 0$) an object. If a choice causes the cumulative weight to exceed the bag capacity $W$, we prune (kill) the node and immediately backtrack to the parent to explore the alternate branch!"
📋

1.1 Problem Statement

Given n = 4 discrete objects, each having an indivisible weight wi and an associated profit pi, and a knapsack of maximum weight capacity W = 8 kg.

🎯 Objective Function (Maximize Profit):

Maximize   P = ∑i=1n (pi · xi)

⚖️ Capacity Constraint (Feasibility):

Subject to:   ∑i=1n (wi · xi) ≤ W = 8 kg
0/1 Binary Decision Property: Each variable xi ∈ {0, 1}. You cannot take fractions of an item, and you cannot take an item more than once. Either you take it whole (xi = 1) or you leave it (xi = 0).

1.3 Backtracking Approach & Bounding Mechanism

In Backtracking, we formulate the solution vector as a 4-tuple X = (x₁, x₂, x₃, x₄). The state-space tree is organized with 4 levels corresponding to the sequential decisions for objects 1 through 4:

🏷️ Node State Representation

Each node in our state-space tree records a state pair:

( cp , cw )
  • cp = Current Profit accumulated so far.
  • cw = Current Weight loaded into the knapsack.
  • Depth / Level = Indicates which item $i$ we are deciding on.

🌿 Branching Logic at Level i

From every viable node at level $(i - 1)$, we branch two ways:

Left Branch (xi = 1): cw += wi,   cp += pi
Right Branch (xi = 0): cw unchanged,   cp unchanged

We always explore the inclusion branch first (standard Depth-First Search order).

✂️ Dual Pruning / Bounding Conditions (How Nodes are Killed)

🛑 Condition 1: Capacity Feasibility Pruning
if (cw > W = 8 kg) ➜ PRUNE & BACKTRACK

If adding object $i$ pushes the cumulative weight beyond the maximum allowable bag limit of 8 kg, this node is declared infeasible (killed). We never generate children under this node!

📉 Condition 2: Upper Bound Optimality Pruning
if (Upper_Bound ≤ Max_Profit_So_Far) ➜ PRUNE

If the maximum potential profit reachable from this sub-tree (current profit plus upper bound on remaining items) cannot beat our best solution found so far, the entire branch is discarded!

4.1 Canonical Backtracking Algorithm

C++ / Pseudocode 
// Global Problem Variables
const int n = 4;
const int W = 8;
int w[] = {2, 3, 4, 5};
int p[] = {3, 5, 6, 10};

int x[4];              // Current decision vector
int best_x[4];         // Best solution vector found
int max_profit = 0;    // Track best profit so far

// Backtracking function to explore state-space tree
void knapsackBacktrack(int i, int cp, int cw) {
    // Base Case: All n items have been decided
    if (i == n) {
        if (cp > max_profit) {
            max_profit = cp;
            for (int k = 0; k < n; k++) best_x[k] = x[k];
        }
        return;
    }

    // CHOICE 1: Include item i (x[i] = 1)
    // Bounding Condition 1: Check capacity feasibility
    if (cw + w[i] <= W) {
        x[i] = 1;
        knapsackBacktrack(i + 1, cp + p[i], cw + w[i]);
    } else {
        // KILLED: Exceeds capacity W = 8 kg (Pruned!)
    }

    // CHOICE 2: Exclude item i (x[i] = 0)
    // Optional Bounding Condition 2: Check upper bound
    if (computeUpperBound(i + 1, cp, cw) > max_profit) {
        x[i] = 0;
        knapsackBacktrack(i + 1, cp, cw);
    } else {
        // PRUNED: Cannot beat current best solution!
    }
}
📐

4.2 Greedy Upper Bound (Fractional Knapsack Relaxation)

To aggressively prune suboptimal right branches, textbooks (Horowitz & Sahni / Neapolitan) define a Bounding Function that computes the maximum conceivable profit reachable from the current state using the Fractional Knapsack greedy relaxation:

Bound(cp, cw, k) = cp + ∑j > k, fitting pj + (Remaining Capacity) × (pnext / wnext)
Why Greedy Bound Works:

Since Fractional Knapsack is an upper bound on 0/1 Knapsack, if even the fractional relaxation cannot beat $\text{max\_profit}$, then no integer solution in that sub-tree ever can!

Condition for Early Pruning:

If $\text{Bound}(cp, cw, k) \le \text{max\_profit}$, we do not even branch into the right child. The entire sub-tree of $2^{n-k}$ nodes is eliminated at once!

⏱️

4.3 Asymptotic Complexity & Paradigm Comparison

⏳ Time Complexity

• Worst Case: O(2ⁿ).
In the worst case (e.g., when knapsack capacity is very large and no node violates capacity), every binary choice is explored, yielding $2^n$ leaf nodes.

• Average Case: Substantially less than $2^n$. Bounding functions prune huge swaths of infeasible and suboptimal branches early.

💾 Space Complexity

• Auxiliary Space: O(n).
The DFS recursion stack only ever holds $n$ stack frames along any active path from root to leaf, and the decision vector requires an array of size $n$.

• Crucial advantage over Dynamic Programming when $W$ is enormous ($W = 10^9$), because DP takes $O(n \cdot W)$ memory!

Paradigm Time Complexity Space Complexity When Best Suited? Exploration Order
Dynamic Programming O(n · W) O(n · W) or O(W) Small to moderate integer capacities $W$. Bottom-Up Tabulation
Backtracking (This Chapter) O(2ⁿ) worst O(n) minimal Very large $W$, moderate $n \le 30$. Depth-First Search (DFS)
Branch and Bound O(2ⁿ) worst Exponential queue Optimization with Best-First bounds. Breadth-First / Priority Queue (LCBB)
