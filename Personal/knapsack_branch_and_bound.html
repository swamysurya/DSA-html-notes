1. 0/1 Knapsack Problem & Branch and Bound Formulation

Discrete indivisibility property, converting maximization to minimization, fixed-size solution representation.

Lecture Transcript • Abdul Bari
📝 Professor Abdul Bari's Lecture: "Here some objects are given. For each object there is some profit and some weight, and there is a bag of capacity 15 kg. The objective is to fill the bag such that the total weight of the objects is less than or equal to 15, and if you take any object you must take the complete object or don't take it at all. It is a maximization problem, but in Branch and Bound we traditionally solve minimization problems. So we convert the signs of profits to negative, solve it using Least Cost Branch and Bound, and convert the result back to positive!"

§1.1 The Given Problem Dataset (Capacity M = 15 kg, n = 4)

We have n = 4 objects and a knapsack of capacity M = 15 kg. Items are pre-sorted in descending order of profit/weight ratio (pi / wi):

Object Index ( i ) Object 1 Object 2 Object 3 Object 4
Profit ( pi ) 10 10 12 18
Weight ( wi in kg ) 2 4 6 9
Ratio ( pi / wi ) 10/2 = 5.0 10/4 = 2.5 12/6 = 2.0 18/9 = 2.0

§1.2 Converting Maximization to Minimization

In theoretical computer science and standard Branch and Bound textbooks (Horowitz & Sahni), Branch and Bound solvers are built as Minimization engines:

Original Problem (Maximization):
Maximize   Profit = ∑ (pi · xi)

We want the highest positive profit.

Branch & Bound Engine (Minimization):
Minimize   Cost = -Profit = -∑ (pi · xi)

We negate the profits and search for the minimum negative cost.

Result Conversion: At the end of the search, when the minimum cost node is found (e.g. -38), we invert the sign back to positive: Maximum Profit = -(-38) = 38!

§1.3 Solution Representation: Fixed Size Tuple

In the lecture, Abdul Bari discusses two choices of solution representation:

1. Variable-Size Representation (Subset List):

Stored as indices of included objects, e.g. {1, 2, 4}. The size of the answer tuple changes depending on how many items are picked.

2. Fixed-Size Representation (0/1 Tuple): ✓ Selected

Stored as an n-tuple X = (x1, x2, x3, x4) where each xi ∈ {0, 1}. Each level in the tree directly corresponds to deciding object i.

2. Cost (ĉ) and Upper Bound (u) Calculation Mechanics

Exact definitions of ĉ (with fractions) and u (without fractions), and the global variable UPPER.

Formulas & Rules

§2.0 The Intuitive Knapsack Analogy: "The 15 kg Jewelry Heist"

🎒 The Core Dilemma: Imagine you are a robber packing a sturdy backpack with a maximum capacity of 15 kg. You are looking at 4 solid, unbreakable items (heavy gold bars, electronics, diamond cases). The strict rule: You cannot slice an electronic device or saw a diamond case in half; you either pack the whole item (xi = 1) or leave it (xi = 0).
📦 1. upper (u) — "The Legal Pack"

What it is: What can you pack right now using only legal, whole objects that fit completely?
At Root: Pack Obj 1 (2kg, $10) + Obj 2 (4kg, $10) + Obj 3 (6kg, $12) = 12 kg. You have 3 kg left, but Obj 4 needs 9 kg. Since you can't break it, you close the zipper.
⇒ Real Cash in Bag = $32 (u = -32).

🚐 2. UPPER — "Cash in the Van"

What it is: The highest confirmed legal cash you have secured in the getaway van so far.
At Root: Since you have a guaranteed bag worth $32, you radio the van: "We already have $32 secured!"
⇒ UPPER = -32 (Benchmark to beat!).

⚡ 3. cost (ĉ) — "The Laser Cutter Fantasy"

What it is: If you had a magic laser cutter and were allowed to turn the remaining 3 kg into gold dust, what is the MAXIMUM possible value this branch could ever dream of?
At Root: $32 + (18/9 × 3) = $38.
⇒ Dream Profit = $38 (ĉ = -38).

🚪 Why We KILL A Branch (The Laser Cutter Test):

Later at Node 7, you find an even better legal pack worth $38, so your van has UPPER = -38 ($38 cash). Now you look down another aisle (Node 5, where you skipped Obj 2). You ask the laser cutter for its fantasy value: it says at best, with magic dust, this aisle can only produce $36 (cost = -36)!

Fantasy Value ($36) < Real Cash in Van ($38) ⇒ ĉ (-36) > UPPER (-38) ⇒ SLAM THE DOOR! (KILL NODE!)

Why waste time searching through drawers in an aisle whose magical maximum is $36, when you already have $38 in cold hard cash in the van?! Prune it immediately!

§2.1 Cost (ĉ) vs Upper Bound (u): The Golden Distinction

For every node in the state space tree, we compute two critical values. Both represent the sum of profits (negated for minimization), but with one crucial difference:

⚖️ 1. Cost ĉ(node) — WITH FRACTION
ĉ = - (Sum of profits of all full items + fraction of next item to completely fill remaining capacity)

Though the 0/1 problem forbids fractions in the final solution, we compute the fractional knapsack relaxation purely for the mathematical bound. Because fractional relaxation gives the optimistic theoretical maximum, ĉ is the absolute lower bound on cost.

🛡️ 2. Upper Bound u(node) — WITHOUT FRACTION
u = - (Sum of profits of only those items that can be included COMPLETELY without taking any fractions)

u is a guaranteed, valid, 100% integer feasible solution value achievable down this path.

§2.2 Global Variable UPPER & The Killing (Pruning) Rule

🔑 How the Global Variable UPPER Works:

  1. Initialization: Before starting, initialize UPPER = ∞.
  2. Updating UPPER: Whenever any generated node yields a smaller (more negative) upper bound:
    If (u < UPPER) → UPPER = u;
  3. The Killing (Pruning) Condition:
    If ĉ(node) > UPPER → KILL THAT NODE!

    WHY? In negative minimization, ĉ > UPPER means the optimistic fractional profit is strictly worse than a real integer solution we already possess! Expanding it would be a complete waste of time.

  4. Retroactive Killing: When UPPER drops to a smaller value (e.g. from -32 to -38), we re-examine all currently alive nodes in the tree. Any alive node whose ĉ > -38 (such as -36 or -32) is immediately KILLED!

§2.3 Numerical Root Node Calculation (Abdul Bari Walkthrough)

🧮 Calculation for Root Node 1 (Capacity M = 15 kg):

Objects: (p1=10, w1=2), (p2=10, w2=4), (p3=12, w3=6), (p4=18, w4=9)
• Object 1: wt = 2 ≤ 15. Accumulated wt = 2, profit = 10.
• Object 2: wt = 4 ≤ 15. Accumulated wt = 2 + 4 = 6, profit = 10 + 10 = 20.
• Object 3: wt = 6 ≤ 15. Accumulated wt = 6 + 6 = 12, profit = 20 + 12 = 32.
• Remaining Capacity: 15 - 12 = 3 kg. Object 4 weighs 9 kg (cannot fit whole).
1. Cost ĉ (WITH FRACTION):
Fractional profit from Obj 4 = (18 / 9) × 3 = 2 × 3 = 6.
Total Profit = 10 + 10 + 12 + 6 = 38.
⇒ Cost ĉ = -38
2. Upper Bound u (WITHOUT FRACTION):
Only complete objects 1, 2, 3 fit (wt = 12 kg ≤ 15 kg).
Total Profit = 10 + 10 + 12 = 32.
⇒ Upper Bound u = -32
3. Global UPPER Update:
Since -32 < ∞ ⇒ UPPER is updated to -32.

§4.1 Formal LC-Branch and Bound Pseudocode

// Abdul Bari Least-Cost Branch and Bound for 0/1 Knapsack
Algorithm Knapsack_LCBB(p[1..n], w[1..n], M):
1. Sort items in descending order of (p[i] / w[i]).
2. UPPER = ∞; Initialize Min-Heap PQ based on Cost ĉ.
3. root.level = 0, root.weight = 0, root.profit = 0.
4. root.cost = CalculateCost(root), root.upper = CalculateUpper(root).
5. UPPER = root.upper; PQ.push(root).
6. While PQ is not empty:
u = PQ.extract_min();
If u.cost > UPPER → Continue (Kill node);
If u.level == n → Record best solution;
// Branch 1: Include item (x[i] = 1)
v_left = CreateChild(u, x=1);
If v_left.weight ≤ M:
v_left.upper = CalculateUpper(v_left);
If v_left.upper < UPPER → UPPER = v_left.upper;
v_left.cost = CalculateCost(v_left);
If v_left.cost ≤ UPPER → PQ.push(v_left);
// Branch 2: Exclude item (x[i] = 0)
v_right = CreateChild(u, x=0);
v_right.upper = CalculateUpper(v_right);
If v_right.upper < UPPER → UPPER = v_right.upper;
v_right.cost = CalculateCost(v_right);
If v_right.cost ≤ UPPER → PQ.push(v_right);
7. Return -UPPER (Max Profit).

#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>

using namespace std;

// Structure representing each object
struct Item {
    int id;
    double profit;
    double weight;
    double ratio;
};

// State Space Tree Node
struct Node {
    int level;              // Index of item considered (0 to n - 1)
    double weight;          // Total accumulated weight so far
    double profit;          // Total accumulated profit so far
    double cost;            // c_hat: Cost WITH fraction (negative)
    double upper;           // u: Upper bound WITHOUT fraction (negative)
    vector<int> x;          // Solution vector (1 = included, 0 = excluded)
};

// Comparator for Min-Heap Priority Queue (Least Cost Branch and Bound)
struct CompareNode {
    bool operator()(const Node& a, const Node& b) {
        return a.cost > b.cost;  // Smallest (most negative) cost has highest priority
    }
};

// Computes Upper Bound 'u' WITHOUT fraction (negated)
double computeUpper(const Node& u, int n, double M, const vector<Item>& items) {
    double total_weight = u.weight;
    double total_profit = u.profit;

    for (int j = u.level; j < n; ++j) {
        if (total_weight + items[j].weight <= M) {
            total_weight += items[j].weight;
            total_profit += items[j].profit;
        }
    }
    return -total_profit;  // Negate for minimization
}

// Computes Cost 'c_hat' WITH fraction (negated)
double computeCost(const Node& u, int n, double M, const vector<Item>& items) {
    double total_weight = u.weight;
    double total_profit = u.profit;

    int j = u.level;
    while (j < n && total_weight + items[j].weight <= M) {
        total_weight += items[j].weight;
        total_profit += items[j].profit;
        j++;
    }

    // Take fraction if room permits
    if (j < n) {
        total_profit += (M - total_weight) * items[j].ratio;
    }

    return -total_profit;  // Negate for minimization
}

// Least Cost Branch and Bound 0/1 Knapsack Solver
double knapsackAbdulBariLCBB(double M, vector<Item> items, vector<int>& best_x) {
    int n = items.size();

    // 1. Pre-sort items in descending order of ratio (p/w)
    sort(items.begin(), items.end(), [](const Item& a, const Item& b) {
        return a.ratio > b.ratio;
    });

    priority_queue<Node, vector<Node>, CompareNode> PQ;
    double UPPER = 1e9;  // Initialized to infinity

    // 2. Initialize Root Node 1
    Node root;
    root.level = 0;
    root.weight = 0.0;
    root.profit = 0.0;
    root.upper = computeUpper(root, n, M, items);
    root.cost = computeCost(root, n, M, items);

    UPPER = root.upper;  // Becomes -32
    PQ.push(root);

    while (!PQ.empty()) {
        Node u = PQ.top();
        PQ.pop();

        // Killing condition: if cost exceeds current UPPER, kill node!
        if (u.cost > UPPER) continue;

        if (u.level == n) {
            best_x = u.x;
            continue;
        }

        int i = u.level;

        // --- Branch 1: INCLUDE Object i (x[i] = 1) ---
        if (u.weight + items[i].weight <= M) {
            Node v_left;
            v_left.level = i + 1;
            v_left.weight = u.weight + items[i].weight;
            v_left.profit = u.profit + items[i].profit;
            v_left.x = u.x;
            v_left.x.push_back(1);

            v_left.upper = computeUpper(v_left, n, M, items);
            if (v_left.upper < UPPER) {
                UPPER = v_left.upper;  // Smaller upper bound found!
            }

            v_left.cost = computeCost(v_left, n, M, items);
            if (v_left.cost <= UPPER) {
                PQ.push(v_left);
            }
        }

        // --- Branch 2: EXCLUDE Object i (x[i] = 0) ---
        Node v_right;
        v_right.level = i + 1;
        v_right.weight = u.weight;
        v_right.profit = u.profit;
        v_right.x = u.x;
        v_right.x.push_back(0);

        v_right.upper = computeUpper(v_right, n, M, items);
        if (v_right.upper < UPPER) {
            UPPER = v_right.upper;
        }

        v_right.cost = computeCost(v_right, n, M, items);
        if (v_right.cost <= UPPER) {
            PQ.push(v_right);
        }
    }

    return -UPPER;  // Convert back to positive maximum profit
}

int main() {
    // Abdul Bari Lecture Dataset: M = 15 kg, n = 4
    double M = 15.0;
    vector<Item> items = {
        {1, 10.0, 2.0, 5.0},    // Obj 1: p=10, w=2, ratio=5.0
        {2, 10.0, 4.0, 2.5},    // Obj 2: p=10, w=4, ratio=2.5
        {3, 12.0, 6.0, 2.0},    // Obj 3: p=12, w=6, ratio=2.0
        {4, 18.0, 9.0, 2.0}     // Obj 4: p=18, w=9, ratio=2.0
    };

    vector<int> best_x;
    double max_profit = knapsackAbdulBariLCBB(M, items, best_x);

    cout << "=== Abdul Bari 0/1 Knapsack LC-BB Solution ===\n";
    cout << "Maximum Profit: " << max_profit << "\n";
    cout << "Fixed-Size Solution Tuple X: (";
    for (size_t i = 0; i < best_x.size(); ++i) {
        cout << best_x[i] << (i + 1 == best_x.size() ? "" : ", ");
    }
    cout << ")\n";
    cout << "Objects Included: ";
    double total_weight = 0.0;
    for (size_t i = 0; i < best_x.size(); ++i) {
        if (best_x[i] == 1) {
            cout << "Object " << (i + 1) << " ";
            total_weight += items[i].weight;
        }
    }
    cout << "\nTotal Weight Consumed: " << total_weight << " / " << M << " kg\n";

    return 0;
}

§4.3 Time and Space Complexity Analysis

⏳ Time Complexity
• Sorting ratios: O(n log n)
• Bound Calculation per node: O(n)
• Worst-Case State Space Tree: O(2n)
⇒ Worst-Case Time: O(n · 2n)
⇒ LC-BB Practical: Fast pruning cuts off majority of nodes!

Notice in Abdul Bari's 4-object tree: instead of exploring all 24 = 16 leaf states and 31 total tree nodes, LC-BB generates only 9 total nodes, immediately pruning dead branches like Nodes 3, 5, 6, and 9!

💾 Space Complexity
• Min-Heap Priority Queue: O(2n) worst-case
• Solution Tuple tracking: O(n)
⇒ Auxiliary Space: O(2n)
• Backtracking Contrast: O(n) recursion stack

Least Cost Branch and Bound trades memory for intelligent search order. By keeping live candidate nodes in a Min-Heap, it always extracts the node with the lowest cost, finding the global optimum much faster than DFS.
